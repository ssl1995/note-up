# 最长递增子序列（LIS）贪心解法

## 核心口诀

> **「短尾小，长序生」**
>
> 让短序列的末尾尽可能小，才能给长序列腾出生长空间。

---

## 为什么能用贪心？

| 条件 | 说明 |
|:---|:---|
| **不要求连续** | 可以跳过元素，随时用更小的数「刷新」记录 |
| **同长度可比较** | 长度相同的子序列，末尾越小，未来潜力越大 |

---

## 贪心策略

维护数组 `tail[i]`：**长度为 i+1 的递增子序列的最小末尾值**

遍历每个数 `num`：
1. **二分查找** `tail` 中第一个 ≥ num 的位置 `index`
2. **找到** → 替换 `tail[index] = num`（同长度，末尾更小）
3. **没找到** → 追加到末尾，长度 +1

---

## 例子演示

输入：`[10, 9, 2, 5, 3, 7, 101, 18]`

| num | 操作 | tail 状态 | 说明 |
|:---:|:---|:---|:---|
| 10 | 追加 | `[10]` | 长度 1 |
| 9 | 替换 | `[9]` | 9 < 10，同长度末尾更小 |
| 2 | 替换 | `[2]` | 2 < 9，继续优化 |
| 5 | 追加 | `[2, 5]` | 5 > 2，长度变 2 |
| 3 | 替换 | `[2, 3]` | 3 < 5，优化长度 2 |
| 7 | 追加 | `[2, 3, 7]` | 长度变 3 |
| 101 | 追加 | `[2, 3, 7, 101]` | 长度变 4 |
| 18 | 替换 | `[2, 3, 7, 18]` | 18 < 101，优化长度 4 |

结果：`size = 4`，即 LIS 长度为 4（如 `[2, 3, 7, 18]` 或 `[2, 3, 7, 101]`）

## 代码模板

```java
public int lengthOfLIS(int[] nums) {
    int[] tail = new int[nums.length];
    int size = 0;

    for (int num : nums) {
        // 二分找第一个 >= num 的位置
        int index = getFirstGE(tail, 0, size, num);
        tail[index] = num;
        if (index == size) size++;
    }
    return size;
}

// [l, r) 范围找第一个 >= t 的下标
private int getFirstGE(int[] nums, int l, int r, int t) {
    while (l < r) {
        int mid = l + (r - l) / 2;
        if (nums[mid] >= t) r = mid;
        else l = mid + 1;
    }
    return l;
}
```

**复杂度**：时间 O(n log n)，空间 O(n)

---

## 与 DP 对比

| | DP O(n²) | 贪心+二分 O(n log n) |
|:---|:---|:---|
| 状态 | `dp[i]` = 以 i 结尾的 LIS 长度 | `tail[i]` = 长度 i+1 的最小末尾 |
| 转移 | 向前遍历所有 j < i | 二分查找插入位置 |
| 适用 | 需要输出具体序列 | 只需长度 |

## 一句话记忆

> **能开新坑开新坑，不能开坑填小坑**
>
> —— 新数比所有末尾都大就延长，否则替换第一个能替换的位置
