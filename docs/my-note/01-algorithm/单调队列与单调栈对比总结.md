# 单调队列与单调栈对比总结

## 1. 为什么滑动窗口最大值用单调队列？

### 1.1 问题特点

滑动窗口有两个核心动作：

- **右边界右移**：新元素进入窗口。
- **左边界右移**：旧元素离开窗口。

需要实时拿到**当前窗口内的最大值**，并且每次查询要 $O(1)$，整体要 $O(n)$。

### 1.2 普通数据结构为什么不行？

| 数据结构 | 问题 |
| --- | --- |
| 优先队列/堆 | 堆顶是最大值，但无法快速删除“已经滑出窗口”的元素。lazy deletion 可以做到 $O(n\log n)$，但不是最优。 |
| 普通队列 | 只能记录进入顺序，无法快速获取最大值。 |
| 单调栈 | 只处理一侧边界（通常是右边界），无法优雅地处理左侧过期元素的移除。 |

### 1.3 单调队列为什么合适？

单调队列（这里用**双端队列**实现）同时满足两个能力：

1. **队头维护当前窗口最大值**：队列中的元素按值**单调递减**，队头始终是窗口最大值。
2. **队尾入队、队头出队**：双端队列支持两侧操作，天然适配滑动窗口的“右进左出”。
3. **过期元素从队头移除**：因为队列中存的是下标，可以判断队头下标是否已经滑出窗口左边界。

> 关键点：窗口内任何一个元素，如果它后面出现了比它**更大或相等**的元素，那它**永远不可能成为最大值**，可以直接从队尾弹掉。这就是维护单调性的核心逻辑。

### 1.4 LC239 代码核心逻辑

```java
Deque<Integer> deque = new ArrayDeque<>();
for (int i = 0; i < n; i++) {
    // 1. 维护单调递减：新元素把队尾更小的全部挤掉
    while (!deque.isEmpty() && nums[i] >= nums[deque.peekLast()]) {
        deque.pollLast();
    }
    // 2. 新元素入队
    deque.offerLast(i);

    // 3. 移除已经滑出左边界的队头
    int l = i - k + 1;
    if (deque.peekFirst() < l) {
        deque.pollFirst();
    }

    // 4. 窗口形成后，队头就是最大值
    if (i >= k - 1) {
        res[i - k + 1] = nums[deque.peekFirst()];
    }
}
```

## 2. 单调队列 vs 单调栈

### 2.1 核心区别

| 维度 | 单调栈（Monotonic Stack） | 单调队列（Monotonic Queue） |
| --- | --- | --- |
| **操作端** | 只有一端：栈顶入、栈顶出 | 两端：队尾入、队头出（双端队列） |
| **元素移除** | 只能从栈顶移除 | 可以从队头和队尾移除 |
| **适用场景** | 处理“右侧/左侧第一个更大/更小元素”问题 | 处理“滑动窗口最值”问题 |
| **时间维度** | 元素只关心入栈和出栈的相对顺序 | 元素关心“有效期”，过期要从队头移除 |
| **典型例题** | 下一个更大元素、接雨水、柱状图中最大矩形 | 滑动窗口最大值、滑动窗口最小值 |

### 2.2 形象理解

- **单调栈**：像一叠盘子，只能从最上面放和取。每个元素被压入时，会把上面所有更小的盘子“弹飞”，然后自己坐上最顶。它关心的是“我下面第一个比我大的/小的”。
- **单调队列**：像一条传送带，新元素从后面上去，旧元素从前面下去。后面新元素可以把前面“不可能再当老大”的元素挤掉，前面过期元素也会被主动踢出。

## 3. 使用场景总结

### 3.1 用单调栈的场景

遇到以下关键词或问题模型时考虑：

1. **下一个更大/更小元素**（Next Greater/Smaller Element）
2. **上一个更大/更小元素**（Previous Greater/Smaller Element）
3. **以某个元素为最小值/最大值的区间范围**
4. **接雨水、柱状图中最大矩形**

**核心问法**：对于当前元素，找左边/右边第一个比它大/小的元素。

### 3.2 用单调队列的场景

遇到以下关键词或问题模型时考虑：

1. **滑动窗口最值**（最大值、最小值）
2. **固定长度子数组的最值**
3. **需要维护一个“有效区间”内最值**的问题

**核心问法**：在一个不断右移、左侧不断过期的窗口中，快速获取最值。

## 5. 一句话总结

> **单调栈解决“一侧相邻比较”问题，单调队列解决“双侧滑动窗口”问题。**
>
> 只要问题涉及**窗口的左右边界同时移动**，并且需要**快速获取窗口最值**，优先考虑**单调队列**；如果只是找某个元素**左侧或右侧第一个更大/更小元素**，优先考虑**单调栈**。
