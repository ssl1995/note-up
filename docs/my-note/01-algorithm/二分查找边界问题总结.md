# 二分查找边界问题总结
## 核心思想：只背一个模板
所有二分边界题本质相同：数组按某个条件 C 呈 `F F F T T T` 二段分布，找**第一个满足 C 的位置**（分界线）。不要背四种变形，背住一个模板 + 一条换算规则即可。
## 唯一模板（左闭右开）
```java
int left = 0, right = nums.length;        // 左闭右开 [0, n)
while (left < right) {
    int mid = left + (right - left) / 2;  // 防溢出
    if (C(nums[mid])) right = mid;        // mid 满足 C → mid 可能就是答案，往左缩
    else left = mid + 1;                  // mid 不满足 → mid 一定不是答案，往右缩
}
return left;   // 第一个满足 C 的下标；全不满足时 = n
```
模板中唯一变化的是条件 C，循环条件、mid 取法、指针移动、返回值永远不变。
## 换算规则：四种变形统一推导
| 要找的 | 条件 C | 返回值 |
| --- | --- | --- |
| 第一个 >= t | nums[i] >= t | left |
| 第一个 > t | nums[i] > t | left |
| 最后一个 <= t | nums[i] > t（取补条件） | left - 1 |
| 最后一个 < t | nums[i] >= t（取补条件） | left - 1 |
规律只有两条：
1. "第一个 X" → C 就是 X，返回 left
2. "最后一个 X" → C 换成 X 的补集（"最后一个 <= t" = "第一个 > t"的位置减 1），返回 left - 1
右边界不需要第二种写法，它只是"左边界的补条件再减 1"。
## 四种情况的完整代码
```java
// ① 第一个 >= target 的下标；不存在时返回 n（即 LC35 的插入位置）
public int firstGreaterEqual(int[] nums, int target) {
    int left = 0, right = nums.length;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] >= target) right = mid;
        else left = mid + 1;
    }
    return left;
}
// ② 第一个 > target 的下标；不存在时返回 n
public int firstGreater(int[] nums, int target) {
    int left = 0, right = nums.length;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] > target) right = mid;
        else left = mid + 1;
    }
    return left;
}
// ③ 最后一个 <= target 的下标；不存在时返回 -1
public int lastLessEqual(int[] nums, int target) {
    int left = 0, right = nums.length;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] > target) right = mid;   // 补条件：先找第一个 > t
        else left = mid + 1;
    }
    return left - 1;
}
// ④ 最后一个 < target 的下标；不存在时返回 -1
public int lastLess(int[] nums, int target) {
    int left = 0, right = nums.length;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] >= target) right = mid;  // 补条件：先找第一个 >= t
        else left = mid + 1;
    }
    return left - 1;
}
```
四个方法逐行对比：只有 if 里的条件 和 return 两行不同，其余完全一样。①② 找第一个用原条件返回 left；③④ 找最后一个用补条件返回 left - 1。
## 为什么模板长这样（理解后不用背）
循环不变量：答案始终在 [left, right) 内，每次迭代区间严格缩小，收缩到 left == right 时就是答案。
- right = mid 而不是 mid - 1：mid 满足 C，它本身可能就是第一个 T，不能排除
- left = mid + 1 而不是 mid：mid 不满足 C，已确定不是答案，必须排除，否则区间不缩小会死循环
- mid 向下取整：配合上面两条，保证区间每次都变小
- 右开区间 right = n：天然涵盖"插入到末尾 n"这个解，无需特判（若 right = n - 1 右闭，就丢了该解，需要额外特判）
## 反例：伪二分（Base 写法的坑）
```java
} else if (nums[mid] > target) {
    right--;   // 每次只缩 1 格
} else {
    left++;    // 每次只缩 1 格
}
```
算出了 mid 却不利用 mid，指针每次只挪一步，本质是披着二分外衣的线性扫描，时间复杂度 O(n)。二分的灵魂是每比较一次砍掉一半：left = mid + 1 / right = mid，才是 O(log n)。
## 考场做题三步
1. 定义 C：答案位置满足什么性质？（LC35：>= target）
2. 验证二段性：C 在数组上是否呈 F F F T T T 单调分布？不满足就不能二分（旋转数组、二分答案题的核心工作就是把 C 构造出来）
3. 套模板选返回值：找"第一个" → 返回 left；找"最后一个" → 用补条件，返回 left - 1
## 边界自检（以 LC34 [5,7,7,8,8,10], t=8 为例）
- 左边界：C = >= 8，返回 left = 3 ✓
- 右边界：C = > 8，left = 5，返回 5 - 1 = 4（最后一个 8）✓
- 注意两种越界：找"第一个 >= t"可能返回 n（全比 t 小）；找"最后一个 <= t"可能返回 -1（全比 t 大），调用处判断一下即可（LC34 判 nums[left] != target 返回 -1 用的就是这个）
## 同类题地图（二分查找家族）
### ① 直接套二段性模板（找边界）
| 题号 | 题目 | 条件 C（找第一个 T） |
| --- | --- | --- |
| LC704 | 二分查找 | 基础模板 |
| LC35 | 搜索插入位置 | nums[i] >= target |
| LC34 | 查找第一个和最后一个位置 | 左边界 >= t；右边界 > t 再 -1 |
| LC278 | 第一个错误的版本 | isBadVersion(i) |
| LC69 | x 的平方根 | 找最后一个 i*i <= x |
| LC374 | 猜数字大小 | guess(i) <= 0 |
### ② 变形：部分有序 / 二段性隐藏
- LC33 搜索旋转排序数组：先判断哪一半有序，再判断 target 在不在有序那一半
- LC153 寻找旋转排序数组最小值：C = nums[i] < nums[right]
- LC162 寻找峰值：nums[i] < nums[i+1] 则峰在右，否则在左
- LC74 搜索二维矩阵：二维压平成一维，或对行、列各二分一次
### ③ 升级：二分答案（值域二分）
题目看不出有序，但答案有单调性（答案 x 可行 → 比 x 大的都可行），对答案区间二分 + check 验证：
- LC875 爱吃香蕉的珂珂（二分速度）
- LC1011 在 D 天内送达包裹（二分运载能力）
- LC410 分割数组的最大值（二分"最大值最小"）
- LC4 寻找两个正序数组中位数（二分划分，hard 天花板）
## 一句话总结
有序 + 查找/边界 → 二分下标；答案有单调性 → 二分答案。统一翻译为"找第一个满足条件的位置"，套左闭右开模板 right = mid / left = mid + 1；"第一个"返回 left，"最后一个"用补条件返回 left - 1，永不特判。
