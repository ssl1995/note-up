## 记忆总口诀
遇到左括号，递归往下包；
右括号字符串尾，收拾结果往返回；
where 记录停在哪，上级接着往下跑；
乘除先算入栈顶，加减最后统一搞。
## 嵌套递归模板核心思想
### 三要素
- 全局变量 `where`：下级函数返回前更新，告诉上级"我解析到了什么位置"。
- 递归函数 `f(i)`：从 `s[i..]` 开始解析，负责计算"自己这一段"的结果并返回。终止条件有两个：遇到字符串结尾，或遇到嵌套条件终止符（如 `)`）。
- 嵌套展开：f(i) 遇到嵌套开始符（如 `(`）时，调用 `f(i+1)` 把嵌套部分整个外包给下级，下级返回的计算结果直接当作一个"数"使用，然后 `i = where + 1` 跳过整个嵌套部分继续解析。
### 执行流程图解（以 "2*(3+4)+5" 为例）
- 第一层 f(0)：读到数字 2，遇到 `*` 入栈，遇到 `(` → 外包给 f(3)。
- 第二层 f(3)：读到 3、+、4，遇到 `)` 终止，返回 7，更新 where=6（指向 `)`）。
- 第一层继续：cur=7（下级的返回值当数用），i=where+1=7，继续读 `+5`。
- 第一层到字符串尾终止，compute 得到 2*7+5=19，返回。
### 为什么返回值能当"数"用
- 括号表达式 `(3+4)` 在语义上就是一个操作数，下级 f 返回的就是这个操作数的值。
- 上级完全不关心括号里有多复杂，嵌套多深都一样——每级只处理自己这一层的"扁平加减乘除"。
## 通用代码（LC772 完整模板）
```java
public class Solution {
  // 全局变量：下级返回前更新，上级通过它知道从哪继续
  public static int where;
  public static int calculate(String str) {
    where = 0;
    return f(str.toCharArray(), 0);
  }
  // s[i..]开始计算，遇到字符串结尾或')'就返回
  // 返回：自己负责这一段的计算结果；返回前更新where
  public static int f(char[] s, int i) {
    int cur = 0;
    ArrayList<Integer> numbers = new ArrayList<>();
    ArrayList<Character> ops = new ArrayList<>();
    // 两个终止条件：i越界（字符串结尾）或遇到')'（嵌套终止符）
    while (i < s.length && s[i] != ')') {
      if (s[i] >= '0' && s[i] <= '9') {
        // 字符是数字：累加进cur，指针前进
        cur = cur * 10 + s[i++] - '0';
      } else if (s[i] != '(') {
        // 字符是运算符：cur连同运算符一起入栈，cur清零
        push(numbers, ops, cur, s[i++]);
        cur = 0;
      } else {
        // 字符是'('：嵌套部分外包给下级f(i+1)
        cur = f(s, i + 1);
        // 下级返回后通过where接力，跳过整个括号
        i = where + 1;
      }
    }
    // 收尾：最后的cur没有后继运算符，补一个'+'送进栈
    push(numbers, ops, cur, '+');
    // 返回前更新where，告诉上级停在哪
    where = i;
    return compute(numbers, ops);
  }
  // 入栈策略：保证numbers里只剩"加减项"
  public static void push(ArrayList<Integer> numbers, ArrayList<Character> ops, int cur, char op) {
    int n = numbers.size();
    if (n == 0 || ops.get(n - 1) == '+' || ops.get(n - 1) == '-') {
      // 栈空或前一个运算符是加减：cur直接入栈
      numbers.add(cur);
      ops.add(op);
    } else {
      // 前一个运算符是乘除：立即与栈顶结算，保证优先级
      int topNumber = numbers.get(n - 1);
      char topOp = ops.get(n - 1);
      if (topOp == '*') {
        numbers.set(n - 1, topNumber * cur);
      } else {
        numbers.set(n - 1, topNumber / cur);
      }
      ops.set(n - 1, op);
    }
  }
  // 统一求和：此时栈里只剩加减，一趟累加出结果
  public static int compute(ArrayList<Integer> numbers, ArrayList<Character> ops) {
    int n = numbers.size();
    int ans = numbers.get(0);
    for (int i = 1; i < n; i++) {
      ans += ops.get(i - 1) == '+' ? numbers.get(i) : -numbers.get(i);
    }
    return ans;
  }
}
```
## 题型区别分析：三题是同一模板的退化关系
### LC227 基本计算器II（+ - * /，无括号）
- 与模板的差异：没有括号，永远不会触发嵌套递归，f(0) 一趟就扫完整个字符串，where 实际用不上。
- 保留的部分：push 的"乘除立即结算、加减延迟结算"机制是本题核心，对应口诀"乘除先算入栈顶，加减最后统一搞"。
- 也可以不用模板：单趟扫描 + 一个栈（或 pre 变量记录上一操作数）即可，遇到 * / 弹出栈顶立即算。
- 题解代码待实现（当前 Solution.calculate 还是 TODO，可直接套用通用模板）。
### LC224 基本计算器（+ -，有括号）
- 与模板的差异：没有 * /，push 里的乘除结算分支永远不会进，栈里天然全是加减项，compute 不变。
- 保留的部分：嵌套递归 + where 接力是本题核心，`(` 外包下级、`)` 终止返回。
- 常见另一种解法：双栈（数字栈 + 操作符栈） iterative 写法，即当前 LC224 Solution 的实现；模板法是它的递归等价物，且更易扩展到 772。
- 注意：双栈写法要处理"括号内第一个字符是负号"的 trick（数字栈补 0），嵌套递归模板则天然规避——`(-3)` 会走 `(` 分支外包，内部 `3` 前面的 `-` 被当作普通运算符，栈底是 0 起始。
- 模板法处理负数说明：f 里 numbers 起始为空，第一个数先进栈再配运算符，`-(3+4)` 实际按 `0-(3+4)` 结算（push 时 n==0 直接入栈 cur=0 之前的 `-` 号会把下级结果变负），细节走一遍 "0-(3+4)" 即可验证。
### LC772 基本计算器III（+ - * /，有括号）
- 完整模板，两个机制都用上：嵌套递归处理括号，push 结算处理乘除优先级。
- 面试通常按 224 → 227 → 772 的顺序递进追问，772 = 224 的括号 + 227 的乘除，掌握模板一题顶三题。
## 模板法 vs 双栈法对比
| 维度 | 嵌套递归模板 | 双栈迭代法 |
| ---- | ---- | ---- |
| 括号处理 | 递归天然匹配嵌套结构 | 需把 `(` 压入操作符栈，`)` 触发弹栈结算 |
| 乘除优先级 | push 时立即与栈顶结算 | 需额外按优先级决定何时结算 |
| 负数/一元减号 | 天然兼容（首个数前补 0 语义） | 需特判 `(`、`+`、`-` 后面补 0 |
| 扩展性 | 加运算符、加括号类型都只需小改 | 改动牵扯双栈结算时机，易错 |
| 空间 | 递归栈 + 每层局部列表 O(n) | 双栈 O(n) |
## 复杂度分析
- 时间复杂度：O(n)。每个字符只被某一层 f 访问一次（嵌套部分通过 where 整体跳过，不会重复扫描），push 和 compute 合计也是线性。
- 空间复杂度：O(n)。递归深度最坏 O(n)（如 `((((1))))`），每层 f 的 numbers/ops 列表合计不超过该层长度。
## 易错点提醒
- 易错点1：忘记在返回前更新 where。少了 `where = i`，上级会拿到旧位置，括号部分被重复解析，结果直接错。
- 易错点2：`i = where + 1` 写成 `i = where`。where 停在 `)` 上，+1 才是跳过右括号。
- 易错点3：收尾时忘记 `push(numbers, ops, cur, '+')`。最后一个数后面没有运算符触发入栈，必须手动补推，否则漏掉最后一项。
- 易错点4：push 里乘除结算后忘记把 ops 栈顶更新为新运算符 op，会导致后续 compute 符号错乱。
- 易错点5：compute 从 numbers.get(0) 开始，循环从 i=1 配对 ops.get(i-1)，下标错位会丢首项或越界。
## 面试回答模板
计算器系列我用一套嵌套递归模板通吃。核心设计是：递归函数 f(i) 负责解析 s[i..] 这一段，遇到字符串结尾或右括号就返回本段结果，返回前把解析到的位置写进全局变量 where。遇到左括号就把括号内部外包给下级递归，下级的返回值就是一个操作数，上级用 i = where + 1 跳过括号继续。同一层内部用两个列表分别存数和运算符，入栈时如果前一个运算符是乘除就立即与栈顶结算，保证优先级；层尾统一把加减项累加出结果。224 只有加减和括号、227 只有加减乘除无括号，都是这套模板的退化，772 是全功能版本。每字符只访问一次，时间 O(n)，空间 O(n)。
