# 滑动窗口"债务模型"精细化总结（LC76 最小覆盖子串 / LC438 找到字符串中所有字符异位词）
适用信号：题目出现"覆盖 / 包含 / 异位词 / 排列"且要求**连续子串**，本质是"窗口词频 vs 目标词频"的约束问题。
一句话模型：把目标串词频记为负数（欠债），窗口字符出现看作还债，用一个标量计数器查账。
## 一、为什么需要债务模型
朴素思路：每个窗口都统计词频，再和目标词频逐位比较，单轮 O(k)，整体 O(m·k) 甚至更差。
债务模型：词频数组只建一次，窗口滑动时增量更新；再用一个标量计数器把"数组是否达标"压缩成一次整数比较。
效果：每轮进窗/出窗各 O(1)，查询 O(1)，整体 O(m+n)，空间 O(k)。
关键机制：计数器**只在词频跨过临界点 0 的瞬间更新**，跨过之前、之后怎么变都不影响它——这是 O(1) 维护正确性的根因。
## 二、统一骨架（三要素）
建债：遍历目标串，cnt[target[i]]--，同时初始化计数器。
还债：r 进窗 cnt[x]++，l 出窗 cnt[x]--；跨过 0 的瞬间同步更新计数器。
查账：计数器达标 ⇔ 窗口合法，此时收集答案或收缩窗口。
## 三、一个数组表达三种状态
cnt[c] < 0：还欠。目标需要 c，窗口里数量还不够。
cnt[c] == 0：恰好。窗口里 c 的数量 == 目标需要的数量。
cnt[c] > 0：盈余。窗口里的 c 超出了需求。
债务模型用一个数组统一表达"需求 + 盈余"，这是它比 sMap/pMap 两个数组写法强的根本原因。
## 四、LC76 最小覆盖子串：完整代码 + 逐段解释
约束特点：包含即可，多还无所谓；窗口可变，要缩到最短。
```java
public String minWindow(String s, String t) {
  char[] cs = s.toCharArray();
  char[] ct = t.toCharArray();
  // 【建债】需要的字符记为负数；cnts[c]<0 表示还欠 c
  int[] cnts = new int[256];
  for (char c : ct) {
    cnts[c]--;
  }
  // 【查账的计数器】debt = 总共还欠多少个字符（按个数计）
  int debt = ct.length;
  int start = 0;
  int len = Integer.MAX_VALUE;
  for (int r = 0, l = 0; r < cs.length; r++) {
    // 【还债·进窗】++ 内联进条件：进窗每轮必做，可以内联
    // 加 1 后仍 <= 0（即原来的 cnts<0），说明还的是刚需债，debt--
    if (cnts[cs[r]]++ < 0) {
      debt--;
    }
    // 【查账达标】债还清了，窗口已覆盖 t
    if (debt == 0) {
      // 【收缩】cnts[cs[l]]>0 说明左端字符是盈余，移出不破坏覆盖
      // 必须用 while：可能连续多个盈余字符，要缩到"再缩就破坏"为止
      while (cnts[cs[l]] > 0) {
        cnts[cs[l++]]--;
      }
      // 【收集】此时 (l, r] 是本轮最短合法窗口
      if (r - l + 1 < len) {
        start = l;
        len = r - l + 1;
      }
    }
  }
  return len == Integer.MAX_VALUE ? "" : s.substring(start, start + len);
}
```
逐段解释：
1. 建债阶段把 t 的词频全部记负，debt 记录"总欠债个数"——注意粒度是**个数**不是种类，因为覆盖类问题只关心"够不够"，不关心"几种达标"。
2. 进窗判断 cnts[x]++ < 0：只有还"刚需债"才 debt--。如果 x 本来就有盈余（cnts[x]>=0），多还的不重复计数——这就是"包含即可"语义在代码里的体现。
3. debt==0 后立刻收缩：把左端所有盈余字符弹掉，保证收集到的窗口是"以 r 结尾的最短合法窗口"。
4. 全局再取 min，得到答案。
走查示例（s="cab", t="ab"，cnts 初始 a=-1, b=-1, debt=2）：
| r | 字符 | 进窗后 cnts 变化 | debt | 动作 |
| --- | --- | --- | --- | --- |
| 0 | c | c: 0→1（盈余，不欠它） | 2 | 不是刚需，debt 不变 |
| 1 | a | a: -1→0 | 1 | 刚需，debt-- |
| 2 | b | b: -1→0 | 0 | 达标；收缩：l=0 处 c 盈余被弹出，窗口变为 "ab"；len=2 |
结果："ab"，正确。
## 五、LC438 Solution3：完整代码 + 逐段解释
约束特点：异位词 = 词频**精确相等**，多一个少一个都不行；窗口固定为 n = p.length()。
```java
public List<Integer> findAnagrams(String s, String p) {
  if (s.length() < p.length()) {
    return new ArrayList<>();
  }
  int m = s.length();
  int n = p.length();
  // 【建债】diff[i] = 窗口词频 - p词频，先减去 p 的词频（记为负）
  int[] diff = new int[26];
  for (int i = 0; i < n; i++) {
    diff[p.charAt(i) - 'a']--;
  }
  // 【查账的计数器】zero = diff 中等于 0 的位置数；初始 = 不在 p 中的字母数
  int zero = 0;
  for (int d : diff) {
    if (d == 0) {
      zero++;
    }
  }
  List<Integer> res = new ArrayList<>();
  char[] cs = s.toCharArray();
  for (int r = 0; r < m; r++) {
    // 【还债·进窗】改前查 → 修改 → 改后查（显式三段式）
    int in = cs[r] - 'a';
    if (diff[in] == 0) {
      zero--;       // 离开临界点：原本恰好，现在被破坏了
    }
    diff[in]++;
    if (diff[in] == 0) {
      zero++;       // 回到临界点：从 -1 还到 0，恰好达标
    }
    // 【出窗】窗口固定为 n，出窗字符位置直接 = r-n，无需 l 指针
    if (r >= n) {
      int out = cs[r - n] - 'a';
      if (diff[out] == 0) {
        zero--;
      }
      diff[out]--;
      if (diff[out] == 0) {
        zero++;
      }
    }
    // 【查账+收集】窗口长度恰好为 n 且词频完全相等
    if (r >= n - 1 && zero == 26) {
      res.add(r - n + 1);
    }
  }
  return res;
}
```
逐段解释：
1. diff 是"窗口词频 − p词频"的合并数组，匹配条件 = diff 全 0，用 zero 计数压缩成 O(1) 查询。
2. 粒度是**种类**而非个数：异位词要求每个字母恰好相等，所以临界判断是 ==0（多还少还都算不达标），zero==26 表示 26 个字母全部恰好匹配。
3. 固定窗口的福利：出窗位置 = r-n，省掉 l 指针、窗口长度判断和"if 还是 while"的思考。
4. 正确性前提：zero==26 成立依赖窗口长度恰好为 n（此时 diff 各位置之和为 0，全 0 ⇔ 词频完全相等），由 r >= n-1 保证。
走查示例（s="abab", p="ab"，diff 初始 a=-1, b=-1，zero=24）：
| r | 进窗 | 出窗 | zero | 收集 |
| --- | --- | --- | --- | --- |
| 0 | a: -1→0 | 无 | 25 | r<1，不收集 |
| 1 | b: -1→0 | 无 | 26 | zero==26 → 收集 0 |
| 2 | a: 0→1（破坏） | 出 a(下标0): 1→0（修复） | 25→26 | 收集 1 |
| 3 | b: 0→1（破坏） | 出 b(下标1): 1→0（修复） | 25→26 | 收集 2 |
结果：[0,1,2]，正确。注意 r=2、3 展示了"进窗破坏、出窗修复"的对称性——这正是固定窗口 diff 模型的典型行为。
## 六、两题分叉点对比（核心记忆表）
| 维度 | LC76 最小覆盖 | LC438 异位词 |
| --- | --- | --- |
| 约束语义 | 包含即可，多还无所谓 | 精确匹配，多一个都不行 |
| 欠债粒度 | 按个数：debt = t.length | 按种类：zero = 未达标字母数 |
| 临界判断 | 进窗 cnts[x]++ < 0 才 debt-- | 跨过 ==0 才更新 zero |
| 达标条件 | debt == 0 | r>=n-1 且 zero == 26 |
| 窗口类型 | 可变：while 收缩 l 求最短 | 固定：出窗位置 = r-n，l 可省 |
| 字符集 | 全 ASCII → int[256] | 小写字母 → int[26] |
| 答案 | 最短子串（记 start+len 取 min） | 所有合法起点（逐轮收集） |
遇到新题先问两个问题："多了行不行？"决定用 <0 还是 ==0；"窗口固定吗？"决定要不要 l + while。
## 七、写法细节与易错点
1. 内联的前提：LC76 进窗还债是**每轮必做**的，可以写成 if (cnts[cs[r]]++ < 0)；收缩出账是**有条件**的，不能写成 cnts[cs[l]]-- > 0，否则判断为假也会多减一次。
2. 不熟内联就用显式三段式（Solution3 的写法）：改前查（离开临界点则 zero--）→ 修改 → 改后查（回到临界点则 zero++），对称、不会错。
3. LC438 若用"默认 0 初始化 + 两个数组"的写法（Solution2），if 判断不能省，否则第一个字符就会误判；用 -1 填充或 diff 负数建债则天然免疫。
4. 微优化：循环前 toCharArray()，避免 charAt 每次的边界检查。
5. 自测用例：LC76 用 "cab"/"ab"（含无关字符）、"aaAABC"/"aaA"（大小写+重复）；LC438 用 "abab"/"ab"（重叠匹配 [0,1,2]）、"bpaa"/"aa"（匹配在尾部）。
## 八、同族题目识别
LC438 找到字符串中所有字符异位词：精确匹配 + 固定窗口。
LC567 字符串的排列：LC438 的布尔版，找到任意一个即返回 true。
LC76 最小覆盖子串：包含即可 + 可变窗口。
LC30 串联所有单词的子串：词袋版，把字符换成单词，模型相同。
LC3 无重复字符的最长子串：可变窗口，约束是"无重复"，思路相近但不需要词频目标。
## 九、一句话记忆
建债为负、过零更新、包含看 <0、精确看 ==0、定窗省 l、变窗 while。
