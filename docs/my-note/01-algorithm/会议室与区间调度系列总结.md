## 二、核心模板：排序 + 小根堆（LC253 / LC2406）

### 一句话核心

> **堆里的每个元素 = 一个"房间/组"，存的值 = 该房间最后一个会议的结束时间。堆的大小 = 已开的房间数。**
> **出堆 + 入堆 = 复用旧房间（只更新结束时间）；只入堆 = 被迫开新房间。**

### 三步走

1. **按开始时间升序排序**：会议按时间先后到来，处理第 i 个时只需决定"复用旧房间"还是"开新房间"。
2. **小根堆堆顶 = 最早空出来的房间**：它是"最有希望被复用"的房间。
3. **逐个判断**：
   - 若堆顶 `end < / <= start`（最早结束的房间已空）→ `poll()` + `offer(end)`，复用，堆大小不变。
   - 若连最早结束的房间都没空 → 所有房间都被占用 → 直接 `offer(end)`，开新房间，堆大小 +1。

### 统一代码模板

```java
// 1、开始时间升序
Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]));

// 2、小根堆，存各房间/组的结束时间
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
minHeap.offer(intervals[0][1]);

// 3、遍历
for (int i = 1; i < intervals.length; i++) {
    int start = intervals[i][0];
    int end = intervals[i][1];
    // 最早结束的房间已空 → 复用（弹出旧结束时间）
    if (minHeap.peek() < start) {   // LC2406 用 <；LC253 用 <=
        minHeap.poll();
    }
    // 写入本会议的结束时间：复用=更新房间，未弹出=开新房间
    minHeap.offer(end);
}
return minHeap.size();
```

### `<` 还是 `<=`？——两题唯一的差异

| 题 | 边界规则 | 出堆条件 |
|---|---|---|
| LC253 会议室 II | `[5,10]` 和 `[10,15]` **不算**冲突，可共用房间 | `堆顶 <= start` 出堆 |
| LC2406 分组 | `[1,5]` 和 `[5,8]` **算**相交（共享数字 5），不能同组 | `堆顶 < start` 出堆 |

**判断口诀**：端点相接算不算重叠？不算 → `<=`（相接可复用）；算 → `<`（必须严格空出）。

### 为什么堆大小就是答案？

- 堆大小只会因"开新房间"增长（每次 poll 都伴随 offer，是复用不是减少）。
- 每次开新房间都是**被迫的**：当时所有已开房间的结束时间都 `> start`，即有"堆大小"个会议真正同时重叠，任何方案都至少需要这么多房间 → 贪心结果就是最少的。
- 等价结论：**答案 = 任意时刻同时进行的会议数的最大值**（最大重叠数）。

### 为什么用 `if` 只弹一个，不用 `while`？

一次只来一个新会议，复用**一个**房间就够了。其他已空闲的房间留在堆里无妨——它们的结束时间小，浮在堆顶附近，下次有会议来优先被复用。弹多个反而把"房间"弄丢了。

### 走一遍例子（LC2406）

`[[1,5],[2,3],[5,10],[6,8],[1,10]]`（已按 start 排序）

| 会议 | 堆顶 | 判断 | 操作 | 堆（结束时间） |
|---|---|---|---|---|
| [1,5] | — | — | 开组1 | [5] |
| [2,3] | 5 | 5<2？否 | 开组2 | [3,5] |
| [5,10] | 3 | 3<5？是 | 复用：弹3入10 | [5,10] |
| [6,8] | 5 | 5<6？是 | 复用：弹5入8 | [8,10] |
| [1,10] | 8 | 8<1？否 | 开组3 | [8,10,10] |

堆大小 = 3 ✓（组1 从 [1,5] 续租到 [6,8]，结束时间 5→8）

## 三、家族扩展：同一思想的变体

### LC252 会议室 I（判断能否全参加）

- 按开始时间排序，检查相邻区间：`intervals[i][0] < intervals[i-1][1]` 则冲突返回 false。
- 一个人 = 只需 1 个房间，是 LC253 的退化版（不需要堆）。

### LC1094 拼车（容量版会议室）

- 上下车点看作事件：`上车 +num`、`下车 -num`，扫描线累加判断峰值是否超 capacity。
- LC253 是"capacity 不限、问峰值是多少"；LC1094 是"峰值给定 capacity、问是否超载"。
- 数据范围小（站点 ≤ 1000）时直接用差分数组最省事。

### LC435 无重叠区间 / LC452 引爆气球（按结束时间排序的贪心）

- **LC435**：按**结束时间**升序排序，遍历保留第一个区间，之后凡是 `start >= 上一保留区间的end` 就保留（不重叠），否则计数删除。答案 = 删除数。
- **LC452**：同样按结束时间排序，每遇到一个 `start > 当前箭位置` 的气球就射一箭（箭位置 = 该气球 end），箭数即答案。
- 两题对偶：**LC452 的箭数 = 最多能选出的互不重叠区间数；LC435 的删除数 = 总数 − 该最大值**。
- 与 LC253 的关系：LC253 求"最大重叠数"（需要几个房间），LC435/452 求"最大不重叠数"（能留几个/几箭）。

## 五、易错点提醒

1. **`<` vs `<=` 是高频坑**：先想清楚"端点相接算不算重叠"。LC253 不算（`<=` 出堆），LC2406 算（`<` 出堆），LC435 不算（`start >= prevEnd` 可保留），LC452 相接也算射中（`start > 箭位置` 才需新箭）。
2. **排序的 key 不要搞混**：求最大重叠数（房间/组）按**开始时间**排；求最大不重叠数（删区间/射箭）按**结束时间**排。
3. **用 `if` 不是 `while`**：一个会议只需复用一个房间。
4. **空数组 / 单区间边界**：先判空，堆先放第一个区间的 end 再从 i=1 遍历。
5. **别忘了 offer**：无论是否复用，当前区间的 end 都要入堆（复用是"弹出旧的、写入新的"）。

## 六、记忆口诀

> 堆=房间，堆顶=最早腾出来的房间；
> 新会议来了，最早的都赶不上 → 开新房间（+1），赶得上 → 续租（弹旧入新，大小不变）；
> 能不能续租看边界：相接可共用 `<=`，相接算冲突 `<`；
> 最大重叠用"开始排序+堆"，最多保留用"结束排序+贪心"。
