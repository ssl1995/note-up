# 二分答案：最小化最大值问题判定指南
## 一句话本质
「求最优值」的直接搜索空间太大，但「给定一个值，判断它可不可行」很容易，且可行性随值单调变化 → 不搜答案，改为二分答案。
## 思维诀窍总览（按优先级）
| 信号 | 具体表现 | 可信度 |
| --- | --- | --- |
| 信号1：问法标志 | "使 XX 的最大值最小" / "使 XX 的最小值最大" | ★★★★★ |
| 信号2：直接求很难 | 求最优值要枚举海量方案，但"给定值验证可行性"很简单 | ★★★★★ |
| 信号3：数据范围 | n 达 10^5~10^6，但答案值域有限（如 <= 10^9），O(n·logU) 能过 | ★★★★ |
| 信号4：答案有明确上下界 | 答案一定落在 [数组min, 数组max] / [1, 总和] 这类天然区间 | ★★★ |
| 信号5：DP 复杂度不够 | 状态设计出来是 O(nk) 甚至更高，明显超时 | ★★★ |
只要信号1 + 信号3 同时出现，基本可以断定是二分答案。
## 诀窍一：识别「问法标志」——最关键的一步
看到以下措辞，条件反射想到二分答案：
- 最小化最大值：最小的最大XXX、能力/成本/差值/时间和的最小可能值
- 最大化最小值：最大的最小XXX、最短距离的最大值、最低收益的最大值
经典例句对照：
- LC2560 打家劫舍IV："窃取能力（=单间房最大金额）的最小值"
- LC410 分割数组的最大值："使各子数组和的最大值最小"
- LC875 爱吃香蕉的珂珂："吃完所有香蕉的最小速度"
- LC1011 轮船运货："运载能力的最低值"
- LC1552 两球之间的磁力："最大化两球间的最小磁力"
- LC2616 最小化数对的最大差值："使数对最大差值最小"
口诀：「最值里面套最值，二分答案没跑了」。
## 诀窍二：验证「单调性」——二分成立的前提
二分答案能用的唯一硬性条件：可行性 check(x) 关于 x 单调。
- 最小化最大值型：x 越大越"宽松"，check 呈 F F F T T T（找第一个 T）
- 最大化最小值型：x 越大越"苛刻"，check 呈 T T T F F F（找最后一个 T）
快速自检法（10秒钟）：
问自己——"如果这个值可行，比它更宽松/更苛刻的值是不是必然可行/不可行？"
- LC2560：cap=5 能偷够 k 间 → cap=6,7,... 必然也能（能偷的房子只会变多）→ 单调 ✓
- LC875：速度 v 能吃完 → 速度 v+1 必然也能吃完 → 单调 ✓
如果 check 不单调（比如"恰好等于 k"而不是"至少 k"），就不能二分，要想别的办法。
注意：很多题把"恰好"转成"至少/至多"就单调了——比如"恰好偷 k 间"不直观，但"至少偷 k 间"单调，且答案处必然取等。
## 诀窍三：「求值难、验证易」的不对称性
这是二分答案存在的根本原因：
- 正面求最优值：要枚举/搜索所有方案再取最值，指数级或高次多项式
- 给定一个候选值验证：通常一遍贪心/简单 DP 就能 O(n) 判断
判断一道题适不适合二分答案，就试着写 check 函数：
"假如有人告诉我答案是 x，我能不能在 O(n) 内验证他有没有骗我？"
- 能 → 二分答案可行
- 不能 → 换思路（DP、搜索、数学）
## 诀窍四：看数据范围倒推复杂度
- n = 10^5：要求 O(n·logX) 或 O(n) → log 级别只能用 30 次左右外层循环 → 二分
- 答案值域 10^9：log2(10^9) ≈ 30 → O(n·30) = 3×10^6，稳过
- 对比：如果答案值域只有 100，那直接枚举都行；值域大 + n 大，才是二分的主场
## 完整决策流程
```
读题
 ├─ 问法是"最小的最大值 / 最大的最小值"？
 │    ├─ 是 → 尝试写 check(x)：O(n) 能验证吗？
 │    │         ├─ 能 → check 单调吗？（自问自检法）
 │    │         │         ├─ 单调 → 二分答案 ✓
 │    │         │         └─ 不单调 → 考虑"至少/至多"改写
 │    │         └─ 不能 → 考虑 DP / 其他
 │    └─ 否 → 常规思路
 └─ n 很大且值域有限？→ 额外佐证二分答案
```
## 二分答案通用模板
最小化最大值（找第一个可行的 x）：
```java
int left = 答案下界, right = 答案上界;   // 如 [min(nums), max(nums)]
while (left < right) {
    int mid = left + (right - left) / 2;
    if (check(mid)) {
        right = mid;        // mid 可行，保留为候选，往小了压
    } else {
        left = mid + 1;     // mid 不可行，必须更大
    }
}
return left;
```
最大化最小值（找最后一个可行的 x）：两种等价写法
```java
// 写法1：直接写，mid 取上中位数防死循环
while (left < right) {
    int mid = left + (right - left + 1) / 2;  // 注意 +1
    if (check(mid)) left = mid;               // 可行，往大了抬
    else right = mid - 1;
}
return left;
// 写法2：统一成"找第一个不可行"，答案 = left - 1（推荐，只有一个模板）
```
## 如何设计 check 函数（各题型套路）
| 题型 | check(x) 的贪心套路 | 代表题 |
| --- | --- | --- |
| 限制单点最大值，凑个数 | 能选就选，越早选越好 | LC2560 打家劫舍IV |
| 分段使每段和 <= x，数段数 | 贪心累加，超了就切一刀 | LC410 分割数组、LC1011 运货 |
| 以速度/效率 x，算总耗时 | 每项向上取整累加，对比上限 | LC875 吃香蕉、LC2187 公交 |
| 保证间距 >= x，数能放几个 | 贪心从左往右能放就放 | LC1552 磁力球、牛客 丢棋子 |
| 数对差值 <= x，凑 k 对 | 排序后相邻配对，能配就配 | LC2616 最小化数对差值 |
共同模式：check 内部几乎都是"一遍扫描 + 能要就要"的贪心，贪心的正确性通常用"早选不劣于晚选"的交换论证。
## 易错点提醒
- 易错点1：把"恰好 k 个"当 check 条件 → 不单调没法二分。改写为"至少 k 个"（最大化/最小化场景下最优处必取等）
- 易错点2：最大化最小值时 mid 忘写 +1 → 死循环。统一用"第一个不可行 - 1"的写法可根治
- 易错点3：二分边界拍脑袋写 [0, 10^9]。尽量用真实值域（min/max/总和），既严谨又快
- 易错点4：check 里用错比较符（< 与 <=）。回到定义念一遍："x 表示最大允许值"，等于 x 当然允许
- 易错点5：与"最大化最小值"混淆收缩方向。记住：可行就继续试探（最小化→往小压，最大化→往大抬），不可行就往回收
- 易错点6：忘了估算复杂度。n=10^5 配 O(n^2) 的 check 照样超时，check 必须 O(n) 或 O(n·logn)
## 二分答案 vs DP 怎么选
- 目标是"总和/数量最大"（如打家劫舍I）→ DP，值直接递推
- 目标是"方案中某最值的最值"（最小化最大值/最大化最小值）→ DP 的状态很难表达"最值约束"，优先考虑二分答案
- 经验：数据范围 n<=5000 且 k 小，O(nk) 的 DP 可能可过；n=10^5 级别基本锁死二分答案

## 面试话术模板
"这道题问的是 XX 最大值的最小值，属于最小化最大值问题。直接求最优值需要枚举所有方案，不可行；但如果给定一个候选值 x，我可以用 XX 贪心在 O(n) 内验证可行性，而且可行性关于 x 单调——x 越大约束越松。所以我二分答案的值域 [下界, 上界]，每次用 check(mid) 判定，总复杂度 O(n·logU)，空间 O(1)。"
