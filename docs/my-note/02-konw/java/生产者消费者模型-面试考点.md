# 生产者消费者模型 - 面试考点详解

## 一、三种实现方式对比

| 实现方式 | 优点 | 缺点 | 适用场景 |
|---------|------|------|---------|
| **wait/notify** | JVM 原生支持，代码简洁 | 容易出错（虚假唤醒、死锁） | 简单场景，学习理解 |
| **ReentrantLock + Condition** | 灵活，多条件队列，可中断 | 代码复杂，需手动释放锁 | 需要精细控制的场景 |
| **BlockingQueue** | 封装完善，不易出错，代码简洁 | 灵活性稍低 | **生产环境推荐** |

## 二、核心面试考点

### 考点1：为什么用 while 而不是 if？

```java
// ❌ 错误写法
if (queue.size() == capacity) {
    wait();  // 虚假唤醒时会出问题
}

// ✅ 正确写法
while (queue.size() == capacity) {
    wait();  // 被唤醒后重新检查条件
}
```

**原因：虚假唤醒（Spurious Wakeup）**
- 线程可能在没有被 notify 的情况下被唤醒（操作系统层面）
- 使用 while 循环，被唤醒后重新检查条件，确保安全

---

### 考点2：notify vs notifyAll

```java
// 场景：两个生产者 P1、P2，一个消费者 C1
// 队列已满，P1 和 P2 都在等待

// 使用 notify：
notify();  // 可能唤醒 P2（同类线程），C1 仍在等待
           // 结果：P2 发现队列仍满，继续等待；C1 没被唤醒 → 死锁！

// 使用 notifyAll：
notifyAll();  // 唤醒 P1、P2、C1
              // C1 消费后，队列有空间，生产者可以继续
```

**结论：**
- 单种角色等待时，notify 可以
- 多种角色等待时，必须用 notifyAll

---

### 考点3：synchronized vs ReentrantLock

| 特性 | synchronized | ReentrantLock |
|-----|-------------|---------------|
| 锁获取 | 自动获取/释放 | 手动 lock/unlock |
| 可中断 | ❌ 不可中断 | ✅ lockInterruptibly() |
| 超时获取 | ❌ 不支持 | ✅ tryLock(timeout) |
| 公平锁 | ❌ 非公平 | ✅ 可设置公平锁 |
| 条件队列 | 1 个（wait/notify） | 多个（Condition） |
| 性能 | JDK 6 后优化，性能接近 | 略高（API 层面） |

**使用建议：**
- 简单同步：synchronized（代码简洁）
- 需要高级特性：ReentrantLock

---

### 考点4：Condition 的优势

```java
// synchronized：只有一个等待队列
synchronized (lock) {
    while (condition) {
        lock.wait();  // 所有线程在同一个队列等待
    }
}

// ReentrantLock：可以创建多个 Condition
private final Condition notFull = lock.newCondition();   // 生产者等待队列
private final Condition notEmpty = lock.newCondition();  // 消费者等待队列

// 生产者等待 notFull
notFull.await();

// 只唤醒消费者，不唤醒生产者
notEmpty.signal();
```

**优势：**
- 分离等待队列，避免唤醒无关线程
- 减少线程竞争，提高效率

---

### 考点5：BlockingQueue 常用方法对比

| 操作类型 | 抛出异常 | 返回特殊值 | 阻塞等待 | 超时等待 |
|---------|---------|-----------|---------|---------|
| 插入 | add(e) | offer(e) | **put(e)** | offer(e, timeout) |
| 移除 | remove() | poll() | **take()** | poll(timeout) |
| 检查 | element() | peek() | - | - |

**记忆口诀：**
- **put/take**：阻塞等待（生产者消费者常用）
- **offer/poll**：返回特殊值（false/null），不阻塞

---

### 考点6：BlockingQueue 实现类对比

| 实现类 | 特点 | 适用场景 |
|-------|------|---------|
| **ArrayBlockingQueue** | 有界数组，固定大小 | 明确容量限制 |
| **LinkedBlockingQueue** | 有界/无界链表，默认无界 | 吞吐量要求高 |
| **SynchronousQueue** | 不存储元素，直接传递 | 传递性场景，如线程池 |
| **PriorityBlockingQueue** | 优先级排序 | 需要优先级的任务 |
| **DelayQueue** | 延迟获取元素 | 定时任务、缓存过期 |

## 三、常见面试问题

### Q1: 什么是虚假唤醒？如何避免？

**虚假唤醒（Spurious Wakeup）：**
- 线程在没有被 notify/notifyAll 的情况下被唤醒
- 操作系统层面可能导致

**避免方法：**
```java
// 使用 while 循环检查条件
while (condition) {
    wait();
}
```

---

### Q2: 生产者消费者模型会导致死锁吗？

**可能的情况：**
```java
// 使用 notify 而不是 notifyAll
// 队列满时，生产者 P1 等待
// 消费者 C1 消费后调用 notify()
// 可能唤醒另一个生产者 P2，而不是消费者
// P2 发现队列仍满，继续等待
// C1 没被唤醒 → 死锁！
```

**解决方案：**
- 使用 notifyAll
- 或使用 ReentrantLock + 两个 Condition

---

### Q3: 如何实现线程安全的单例模式？

```java
// 双重检查锁（DCL）
public class Singleton {
    private static volatile Singleton instance;
    
    private Singleton() {}
    
    public static Singleton getInstance() {
        if (instance == null) {           // 第一次检查
            synchronized (Singleton.class) {
                if (instance == null) {   // 第二次检查
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

**关键点：**
- `volatile`：防止指令重排序
- 双重检查：减少同步开销

---

### Q4: 线程池的核心原理？

```java
// 线程池核心就是生产者消费者模型
// 生产者：提交任务的线程
// 消费者：工作线程
// 缓冲区：任务队列（BlockingQueue）

public class ThreadPoolExecutor {
    private final BlockingQueue<Runnable> workQueue;
    
    public void execute(Runnable command) {
        workQueue.offer(command);  // 生产任务
    }
    
    // 工作线程
    class Worker {
        public void run() {
            while (true) {
                Runnable task = workQueue.take();  // 消费任务
                task.run();
            }
        }
    }
}
```

### Q5: 如何设计一个阻塞队列？

```java
public class MyBlockingQueue<E> {
    private final Queue<E> queue = new LinkedList<>();
    private final int capacity;
    private final ReentrantLock lock = new ReentrantLock();
    private final Condition notFull = lock.newCondition();
    private final Condition notEmpty = lock.newCondition();
    
    public void put(E e) throws InterruptedException {
        lock.lock();
        try {
            while (queue.size() == capacity) {
                notFull.await();
            }
            queue.offer(e);
            notEmpty.signal();
        } finally {
            lock.unlock();
        }
    }
    
    public E take() throws InterruptedException {
        lock.lock();
        try {
            while (queue.isEmpty()) {
                notEmpty.await();
            }
            E item = queue.poll();
            notFull.signal();
            return item;
        } finally {
            lock.unlock();
        }
    }
}
```

## 四、应用场景

| 场景 | 说明 |
|-----|------|
| **线程池** | 任务提交（生产）→ 任务队列 → 工作线程（消费） |
| **消息队列** | 生产者发送消息 → MQ 队列 → 消费者消费消息 |
| **日志系统** | 业务线程写日志（生产）→ 日志队列 → 日志线程写磁盘（消费） |
| **数据管道** | 数据采集（生产）→ 缓冲区 → 数据处理（消费） |
