# MySQL锁机制总结
## 一、锁的分类
MySQL锁按粒度可分为三大类：
- **全局锁**：锁定整个数据库实例。
- **表级锁**：锁定整张表，包括表锁、元数据锁(MDL)、意向锁、AUTO-INC锁。
- **行级锁**：锁定某行或行之间的间隙，包括记录锁、间隙锁、临键锁、插入意向锁。
## 二、全局锁
**命令**：`flush tables with read lock;`（简称FTWRL）
**释放**：`unlock tables;` 或会话断开。
**特点**：加锁后整个库进入只读状态，所有DML和DDL都会被阻塞。
**应用场景**：全库逻辑备份，例如使用mysqldump导出数据。
**优化方案**：InnoDB在可重复读隔离级别下，可以使用 `mysqldump --single-transaction` 参数，通过MVCC一致性读避免加全局锁，备份期间不影响业务写入。
## 三、表级锁
### 1. 表锁
**加锁命令**：`lock tables t read;` 或 `lock tables t write;`
**释放命令**：`unlock tables;` 或会话结束自动释放。
- **读锁**：本线程和其他线程都只能读取该表，不能写入。
- **写锁**：本线程可以读写，其他线程读写都被阻塞。
- **注意**：`lock tables` 会限制当前线程只能操作被锁住的表，不能访问其他未锁表。
### 2. 元数据锁（MDL）
MDL不需要显式加锁，MySQL会自动为表操作添加。
- **读锁**：对表执行增删改查（DML）时，自动加MDL读锁。
- **写锁**：对表结构做变更（DDL）时，自动加MDL写锁。
**兼容性**：读锁之间不互斥；读锁与写锁、写锁与写锁互斥。
**典型风险**：长事务持有某表的MDL读锁，此时执行DDL需要MDL写锁，会被阻塞；而DDL后续的DML请求又会排队等待MDL读锁，导致表短时间内不可用。
**建议**：执行DDL前先检查是否有长事务；或使用相关工具/参数控制超时和自动kill。
### 3. 意向锁
意向锁是表级锁，表示事务稍后要对表中某些行加共享锁或排他锁。
- **意向共享锁(IS)**：事务准备对某些行加S锁。
- **意向排他锁(IX)**：事务准备对某些行加X锁。
**作用**：让表锁与行锁冲突判断更高效，不需要遍历每一行。
**兼容性**：IS与IX之间兼容；IX与表级S/X锁冲突。
### 4. AUTO-INC锁
用于自增主键的分配，属于表级锁。
- **老版本**：语句执行结束后才释放，并发插入性能较差。
- **MySQL 5.1.22+ / InnoDB**：引入 `innodb_autoinc_lock_mode` 参数：
  - `0`：传统模式，语句结束释放AUTO-INC锁。
  - `1`（默认）：普通insert使用轻量级mutex；bulk insert保留AUTO-INC锁。
  - `2`：所有插入都使用mutex，性能最高；但要求binlog格式为row，保证主从一致。
## 四、行级锁
InnoDB支持行级锁，MyISAM不支持。
**两阶段锁协议**：行锁在需要时加上，在事务提交时才释放。因此应尽量把最可能引发冲突的加锁操作放在事务后面，减少锁持有时间，降低死锁概率。
### 1. 记录锁（Record Lock）
锁住具体的索引记录。
- **S锁（共享锁）**：允许读取，多个事务可同时持有。
- **X锁（排他锁）**：只允许当前事务修改，其他事务不能加S/X锁。
### 2. 间隙锁（Gap Lock）
锁住索引记录之间的间隙，不包含记录本身。
- **作用**：防止幻读，阻止其他事务在间隙中插入新记录。
- **生效范围**：仅在可重复读（RR）隔离级别下生效；读已提交（RC）下不使用间隙锁。
### 3. 临键锁（Next-Key Lock）
Record Lock + Gap Lock 的组合，锁住记录本身及其前面的间隙。
- InnoDB默认的行锁算法，用于RR隔离级别下解决幻读问题。
- 当查询条件命中唯一索引且为等值查询并命中记录时，可退化为Record Lock。
### 4. 插入意向锁（Insert Intention Lock）
插入操作前设置的一种间隙锁，表示事务意图在某个间隙插入记录。
- 与Gap Lock冲突：如果目标间隙已被其他事务加了Gap Lock，插入会被阻塞。
- 多个插入同一间隙但不冲突的位置时，插入意向锁之间可兼容。
## 五、核心要点
- InnoDB默认使用行级锁，行锁基于索引实现；没有合适索引时，行锁会退化为表锁。
- 事务要遵循两阶段锁协议，合理安排加锁顺序，降低死锁概率。
- RR隔离级别通过Next-Key Lock防止幻读；RC隔离级别只使用记录锁，性能更好但可能出现幻读。
- MDL锁问题多出现在长事务+DDL场景，执行结构变更前务必排查长事务。
- 全局锁影响范围最大，生产环境尽量使用 `--single-transaction` 等替代方案做逻辑备份。
