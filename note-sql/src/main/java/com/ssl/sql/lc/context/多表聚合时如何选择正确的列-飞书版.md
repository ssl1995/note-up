# 多表聚合时如何选择正确的列
## 1. 问题根源：CROSS JOIN + LEFT JOIN 后的 NULL 值
### 表关系图
```
Students (t1)          Subjects (t2)          Examinations (t3)
+------------+         +--------------+       +------------+--------------+
| student_id |         | subject_name |       | student_id | subject_name |
| student_name|        +--------------+       +------------+--------------+
+------------+                ↑                      ↑
     │                        │                      │
     └────────────────────────┴──────────────────────┘
                    CROSS JOIN + LEFT JOIN
```
### 关键区别
| 列 | 来源 | 是否可能为 NULL | 原因 |
|---|------|---------------|------|
| `t1.student_id` | Students | ❌ 不会 | 主表，一定有值 |
| `t1.student_name` | Students | ❌ 不会 | 主表，一定有值 |
| `t2.subject_name` | Subjects | ❌ 不会 | CROSS JOIN 的右表，一定有值 |
| `t3.subject_name` | Examinations | ✅ 可能 | LEFT JOIN 的右表，无匹配时为 NULL |
## 2. 为什么 `t3.subject_name` 会出错？
### 错误 SQL 的问题
```sql
select t1.student_id,
       t1.student_name,
       t3.subject_name,  -- ❌ 错误！可能是 NULL
       count(t3.subject_name) as 'attended_exams'
```
当某个学生**没有参加某科目考试**时：
- `t3.subject_name` = `NULL`
- `COUNT(t3.subject_name)` = `0`（因为 COUNT 忽略 NULL）
- 但 `t3.subject_name` 显示为 `NULL`，而不是科目名！
### 实际数据示例
| student_id | student_name | t2.subject_name | t3.subject_name | COUNT(t3.subject_name) |
|-----------|-------------|-----------------|-----------------|----------------------|
| 2 | Bob | Math | Math | 1 |
| 2 | Bob | Physics | **NULL** | **0** |
| 2 | Bob | Programming | Programming | 1 |
**如果 SELECT 用 `t3.subject_name`，Bob 的 Physics 行会显示 `NULL`，而不是 `Physics`！**
## 3. 核心原则：SELECT 列的选择规则
### 规则：SELECT 中的列必须来自"确定有值"的表
| JOIN 类型 | 左表 | 右表 | SELECT 时选谁？ |
|----------|------|------|---------------|
| `CROSS JOIN` | 有值 | 有值 | 任选 |
| `INNER JOIN` | 有值 | 有值 | 任选 |
| `LEFT JOIN` | 有值 | **可能 NULL** | **选左表** |
| `RIGHT JOIN` | **可能 NULL** | 有值 | **选右表** |
| `FULL JOIN` | **可能 NULL** | **可能 NULL** | 用 `COALESCE` |
## 4. 多表聚合时的列选择总结
### 场景：A LEFT JOIN B ON A.key = B.key
```sql
SELECT 
    A.id,           -- ✅ 选 A，一定有值
    A.name,         -- ✅ 选 A，一定有值
    B.value,        -- ❌ 危险！可能是 NULL
    COUNT(B.id)     -- ✅ 正确，COUNT 忽略 NULL
FROM A
LEFT JOIN B ON A.id = B.id
GROUP BY A.id, A.name
```
### 正确做法：用 COALESCE 或选左表列
```sql
SELECT 
    A.id,
    A.name,
    COALESCE(B.value, '默认值') AS value,  -- ✅ 处理 NULL
    COUNT(B.id)
FROM A
LEFT JOIN B ON A.id = B.id
GROUP BY A.id, A.name
```
## 5. 针对 1280 题的完整解析
### 正确 SQL（用 t2.subject_name）
```sql
SELECT 
    t1.student_id,
    t1.student_name,
    t2.subject_name,        -- ✅ 来自 Subjects，一定有值
    COUNT(t3.subject_name)  -- ✅ COUNT 忽略 NULL，正确统计
FROM Students t1
CROSS JOIN Subjects t2      -- t1 × t2 = 所有学生 × 所有科目
LEFT JOIN Examinations t3   -- t3 可能无匹配，为 NULL
    ON t1.student_id = t3.student_id 
    AND t2.subject_name = t3.subject_name
GROUP BY t1.student_id, t1.student_name, t2.subject_name
ORDER BY t1.student_id, t2.subject_name;
```
### 错误 SQL（用 t3.subject_name）
```sql
SELECT 
    t1.student_id,
    t1.student_name,
    t3.subject_name,        -- ❌ 来自 Examinations，可能是 NULL
    COUNT(t3.subject_name)
...
```
**结果对比：**
| student_id | student_name | subject_name | attended_exams |
|-----------|-------------|--------------|---------------|
| 2 | Bob | **NULL** ❌ | 0 |
| 2 | Bob | **Physics** ✅ | 0 |
## 6. 通用判断流程图
```
SELECT 列时，问自己：
│
├─ 这个列来自哪张表？
│   ├─ 来自 CROSS JOIN 的任意一侧 → ✅ 可以用
│   ├─ 来自 INNER JOIN 的任意一侧 → ✅ 可以用
│   ├─ 来自 LEFT JOIN 的左表 → ✅ 可以用
│   ├─ 来自 LEFT JOIN 的右表 → ⚠️ 可能是 NULL，需要处理
│   └─ 来自 RIGHT JOIN 的右表 → ✅ 可以用
│
└─ 如果是 LEFT JOIN 右表的列，怎么办？
    ├─ 需要显示值 → 用 COALESCE(列, '默认值')
    ├─ 需要统计数量 → 用 COUNT(列)，自动忽略 NULL
    └─ 需要筛选 → 用 IS NULL 或 IS NOT NULL
```
## 7. 记忆口诀
> **"SELECT 选主表，COUNT 选从表"**
> 
> - **主表**：确定有值的表（CROSS JOIN 两侧、LEFT JOIN 左表）
> - **从表**：可能为 NULL 的表（LEFT JOIN 右表）
> 
> 显示数据用主表列，统计数量用从表列。
