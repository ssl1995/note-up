# 1661. 每台机器的进程平均运行时间

## 1. 题目描述

表：`Activity`

| Column Name   | Type |
|---------------|------|
| machine_id    | int  |
| process_id    | int  |
| activity_type | enum |
| timestamp     | float|

- `machine_id`：机器 ID。
- `process_id`：进程 ID。
- `activity_type`：枚举值，仅取 `'start'` 或 `'end'`。
- `timestamp`：浮点型时间戳（秒）。
- 主键为 `(machine_id, process_id, activity_type)`。
- 同一台机器的同一个进程，必然有一对且仅有一对 `start` 和 `end` 记录，且 `start` 时间戳一定小于 `end` 时间戳。

**目标**：计算每台机器完成一个进程任务的平均耗时，结果保留 3 位小数，列名为 `processing_time`。

进程耗时 = 该进程的 `end` 时间戳 − 该进程的 `start` 时间戳。  
机器平均耗时 = 该机器上所有进程耗时之和 ÷ 该机器上的进程数量。

---

## 2. SQL 考点分析

| 考点 | 说明 |
|------|------|
| **自连接（Self Join）** | 把 `start` 行和 `end` 行通过 `machine_id`、`process_id` 匹配起来，再求差值。 |
| **聚合函数** | `AVG()` / `SUM()` / `COUNT()` / `MAX()` / `MIN()`，按机器维度聚合结果。 |
| **数值格式化** | `ROUND(x, 3)` 用于保留 3 位小数。 |
| **条件聚合** | 利用 `CASE WHEN` / `IF()` 在 `SUM` 中对 `start` 取负、`end` 取正，实现 `SUM(end) - SUM(start)`。 |
| **子查询/CTE** | 先按 `(machine_id, process_id)` 计算每个进程耗时，再求平均。 |
| **窗口函数（可选）** | `LEAD(timestamp)` 按进程时间顺序取下一行的 `end` 时间戳。 |
| **关键字转义** | `timestamp` 是 SQL 关键字，写生产代码时建议用反引号（MySQL）或双引号（PostgreSQL）包裹。 |

---

## 3. 常见解法

### 解法一：自连接（最直观）

把表当成两张表，一张只取 `start`，另一张只取 `end`，按机器和进程连接。

```sql
SELECT
    a.machine_id,
    ROUND(AVG(b.timestamp - a.timestamp), 3) AS processing_time
FROM Activity a
JOIN Activity b
    ON a.machine_id = b.machine_id
    AND a.process_id = b.process_id
WHERE a.activity_type = 'start'
  AND b.activity_type = 'end'
GROUP BY a.machine_id;
```

**优点**：思路直接，容易理解。  
**缺点**：对同一个表做了两次扫描并连接，执行计划相对重；大数据量下不如单表聚合高效。

---

### 解法二：条件聚合（推荐 / 最优）

利用 `start` 时间戳取负、`end` 时间戳取正的特性：

```sql
SELECT
    machine_id,
    ROUND(
        SUM(CASE WHEN activity_type = 'end' THEN timestamp ELSE -timestamp END)
        / COUNT(DISTINCT process_id),
        3
    ) AS processing_time
FROM Activity
GROUP BY machine_id;
```

**优点**：

- 只需**单表一次扫描**，不需要连接或窗口函数。
- 计算量少，性能最好。
- 代码简洁。

**注意**：

- 依赖题设“每个进程都有且只有一对 `start`/`end`”。
- `COUNT(DISTINCT process_id)` 得到每台机器的进程数，用于求平均。

---

### 解法三：子查询 / CTE（先算每个进程耗时，再求平均）

```sql
WITH process_time AS (
    SELECT
        machine_id,
        process_id,
        MAX(`timestamp`) - MIN(`timestamp`) AS duration
    FROM Activity
    GROUP BY machine_id, process_id
)
SELECT
    machine_id,
    ROUND(AVG(duration), 3) AS processing_time
FROM process_time
GROUP BY machine_id;
```

**优点**：语义清晰，先得到每个进程的耗时，再聚合到机器维度。  
**缺点**：需要两次 `GROUP BY`，但对这道题的数据规模完全可以忽略。

---

### 解法四：窗口函数 `LEAD`

```sql
WITH t AS (
    SELECT
        machine_id,
        process_id,
        `timestamp`,
        activity_type,
        LEAD(`timestamp`) OVER (
            PARTITION BY machine_id, process_id
            ORDER BY `timestamp`
        ) AS end_time
    FROM Activity
)
SELECT
    machine_id,
    ROUND(AVG(end_time - `timestamp`), 3) AS processing_time
FROM t
WHERE activity_type = 'start'
GROUP BY machine_id;
```

**优点**：适合需要保留明细行的场景。  
**缺点**：引入了窗口函数，执行开销通常高于纯聚合；对于本题有些“杀鸡用牛刀”。

---

## 4. 最优 SQL

从**性能、简洁性、可读性**三个维度综合考虑，**条件聚合写法**是最优解：

```sql
SELECT
    machine_id,
    ROUND(
        SUM(CASE WHEN activity_type = 'end' THEN `timestamp` ELSE -`timestamp` END)
        / COUNT(DISTINCT process_id),
        3
    ) AS processing_time
FROM Activity
GROUP BY machine_id;
```

### 为什么它最优？

1. **单表扫描**：不需要自连接，也不需要窗口函数排序，减少了一次读取和匹配的开销。
2. **数学上等价**：

   ```text
   SUM(end) - SUM(start) = (end1 + end2 + ...) - (start1 + start2 + ...)
                       = (end1 - start1) + (end2 - start2) + ...
   ```

   正好是“所有进程耗时之和”。
3. **聚合维度少**：只需要按 `machine_id` 分组一次。
4. **结果符合要求**：再用 `COUNT(DISTINCT process_id)` 除以进程数量，最后用 `ROUND(..., 3)` 保留 3 位小数。

---

## 5. 小结

| 解法 | 核心思想 | 推荐指数 | 适用场景 |
|------|---------|---------|---------|
| 自连接 | `start` 与 `end` 行配对 | ⭐⭐⭐ | 初学者理解题意 |
| **条件聚合** | `SUM(end - start)` 一次性聚合 | ⭐⭐⭐⭐⭐ | **性能最优，推荐** |
| 子查询/CTE | 先算每个进程耗时再平均 | ⭐⭐⭐⭐ | 需要保留中间结果 |
| 窗口函数 `LEAD` | 取同一进程的下一条时间戳 | ⭐⭐⭐ | 需要明细行或更复杂的相邻行分析 |

**结论**：在 LeetCode 1661 这道题中，**条件聚合（解法二）是最优 SQL**。
