# 570. 至少有5名直接下属的经理
## 1. 题目描述
**表结构：**
- `Employee`：`id`（主键）、`name`、`department`、`managerId`（指向 `id` 的外键）
**目标：** 找出至少有 5 个直接下属的经理，返回经理的 `name`。
**关键理解：** `managerId` 指向该员工的直属经理的 `id`，一个经理可以有多个下属。
## 2. SQL 考点分析
| 考点 | 说明 |
|------|------|
| **自连接（Self Join）** | 员工表自己连接自己，`e.id = sub.managerId` |
| **GROUP BY 分组** | 按经理分组，统计每个经理的下属数量 |
| **HAVING 过滤** | 对分组后的结果进行筛选，`COUNT >= 5` |
| **聚合函数 COUNT** | 统计每个分组的记录数 |
## 3. GROUP BY + HAVING 详解（重点！）
### 3.1 基础概念
| 子句 | 作用 | 执行顺序 | 能否用聚合函数 |
|------|------|---------|-------------|
| `WHERE` | 对**单行数据**过滤 | 在 GROUP BY 之前 | ❌ 不能 |
| `GROUP BY` | 将数据**分组** | 在 WHERE 之后 | - |
| `HAVING` | 对**分组结果**过滤 | 在 GROUP BY 之后 | ✅ 可以 |
### 3.2 执行流程图
```
原始数据
    ↓
WHERE 过滤（单行级别）
    ↓
GROUP BY 分组（按指定列分组）
    ↓
聚合计算（COUNT/SUM/AVG 等）
    ↓
HAVING 过滤（分组级别）
    ↓
SELECT 输出
```
### 3.3 举例说明
**原始数据：**
| id | name | managerId |
|---|------|----------|
| 101 | John | NULL |
| 102 | Dan | 101 |
| 103 | James | 101 |
| 104 | Amy | 101 |
| 105 | Anne | 101 |
| 106 | Ron | 101 |
**步骤 1：自连接（CROSS JOIN 效果）**
```sql
SELECT * FROM Employee e, Employee sub ORDER BY e.id;
```
结果：6 × 6 = 36 行（笛卡尔积）
| e.id | e.name | sub.id | sub.name | sub.managerId |
|-----|--------|-------|---------|--------------|
| 101 | John | 101 | John | NULL |
| 101 | John | 102 | Dan | 101 |
| 101 | John | 103 | James | 101 |
| 101 | John | 104 | Amy | 101 |
| 101 | John | 105 | Anne | 101 |
| 101 | John | 106 | Ron | 101 |
| 102 | Dan | 101 | John | NULL |
| ... | ... | ... | ... | ... |
**步骤 2：自连接（INNER JOIN 效果）**
```sql
SELECT * FROM Employee e JOIN Employee sub ON e.id = sub.managerId ORDER BY e.id;
```
结果：只有 5 行（John 的 5 个下属）
| e.id | e.name | sub.id | sub.name | sub.managerId |
|-----|--------|-------|---------|--------------|
| 101 | John | 102 | Dan | 101 |
| 101 | John | 103 | James | 101 |
| 101 | John | 104 | Amy | 101 |
| 101 | John | 105 | Anne | 101 |
| 101 | John | 106 | Ron | 101 |
**步骤 3：GROUP BY 分组**
```sql
SELECT e.name, COUNT(sub.id) AS sub_count
FROM Employee e
JOIN Employee sub ON e.id = sub.managerId
GROUP BY e.id, e.name;
```
结果：
| name | sub_count |
|------|----------|
| John | 5 |
**步骤 4：HAVING 过滤**
```sql
SELECT e.name, COUNT(sub.id) AS sub_count
FROM Employee e
JOIN Employee sub ON e.id = sub.managerId
GROUP BY e.id, e.name
HAVING COUNT(sub.id) >= 5;
```
结果：
| name | sub_count |
|------|----------|
| John | 5 |
## 4. 常见解法
### 解法一：自连接 + GROUP BY + HAVING（推荐）
```sql
SELECT e.name
FROM Employee e
JOIN Employee sub ON e.id = sub.managerId
GROUP BY e.id, e.name
HAVING COUNT(sub.id) >= 5;
```
**优点：** 逻辑清晰，直接表达"经理-下属"关系。
### 解法二：子查询（先统计，再筛选）
```sql
SELECT name
FROM Employee
WHERE id IN (
    SELECT managerId
    FROM Employee
    GROUP BY managerId
    HAVING COUNT(*) >= 5
);
```
**优点：** 不需要自连接，子查询先统计经理的下属数。
**缺点：** 如果 `managerId` 有 NULL 值，需要额外处理。
### 解法三：窗口函数（高级）
```sql
SELECT DISTINCT name
FROM (
    SELECT 
        name,
        COUNT(*) OVER (PARTITION BY managerId) AS sub_count
    FROM Employee
) t
WHERE sub_count >= 5;
```
**优点：** 不需要 GROUP BY，用窗口函数直接统计。
**缺点：** 代码稍复杂，性能不一定更好。
## 5. 最优 SQL
**推荐解法一（自连接 + GROUP BY + HAVING）：**
```sql
SELECT e.name
FROM Employee e
JOIN Employee sub ON e.id = sub.managerId
GROUP BY e.id, e.name
HAVING COUNT(sub.id) >= 5;
```
**原因：**
1. 语义最清晰，直接表达"经理-下属"关系
2. 不需要子查询，一次连接完成
3. `HAVING` 直接对分组结果过滤，简洁高效
## 6. 易错点提醒
| 易错点 | 说明 |
|--------|------|
| **WHERE vs HAVING** | `WHERE` 不能跟聚合函数，`HAVING` 可以 |
| **GROUP BY 字段** | 必须包含 `e.id` 和 `e.name`，否则可能报错 |
| **NULL 值处理** | `managerId` 为 NULL 的记录不会参与连接，自动排除 |
| **COUNT(*) vs COUNT(列)** | 本题用 `COUNT(*)` 或 `COUNT(sub.id)` 都可以 |
## 7. 小结
| 解法 | 核心思想 | 推荐指数 |
|------|---------|---------|
| **自连接 + GROUP BY + HAVING** | 经理-下属配对，分组统计 | ⭐⭐⭐⭐⭐ |
| 子查询 | 先统计经理下属数，再筛选 | ⭐⭐⭐⭐ |
| 窗口函数 | 用窗口函数统计，DISTINCT 去重 | ⭐⭐⭐ |
**结论：** 本题最优解是**自连接 + GROUP BY + HAVING**，它能直接表达业务逻辑，代码简洁高效。
