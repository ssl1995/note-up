# 打家劫舍IV（LC2560 · 中等）
## 题目描述
沿街有一排连续的房屋，每间房屋内都藏有一定的现金。小偷计划从这些房屋中窃取现金，由于相邻的房屋装有相互连通的防盗系统，所以小偷不会窃取相邻的房屋。小偷的「窃取能力」定义为他在窃取过程中能从单间房屋中窃取的最大金额。给定整数数组 nums 表示每间房屋存放的现金金额，另给整数 k 表示窃贼将会窃取的最少房屋数（题目保证总能窃取至少 k 间）。返回小偷的最小窃取能力。
示例1：
```
输入：nums = [2,3,5,9], k = 2
输出：5
```
示例2：
```
输入：nums = [2,7,9,3,1], k = 2
输出：2
解释：
- 共有 7 种窃取至少 2 间房屋的方式
- 其中窃取下标 0 和 4 处的房屋时，窃取能力为 max(nums[0], nums[4]) = 2，是所有方案中最小的
```
提示：
- 1 <= nums.length <= 10^5
- 1 <= nums[i] <= 10^9
- 1 <= k <= (nums.length + 1) / 2
## 解法概览
| 解法 | 思路 | 核心公式 | 时间复杂度 | 空间复杂度 |
| ----- | ----- | ----- | ----- | ----- |
| 解法1 | 二分答案 + 贪心判定 | `nums[i] <= cap 就偷，i += 2` | O(n·logU) | O(1) |
| 解法2 | 二分答案 + DP判定 | `f(i)=max(f(i-1), f(i-2)+1)` | O(n·logU) | O(1) 可滚动 |
| 解法3 | 纯 DP（minimax） | `dp[i][j] = min(偷/不偷)` | O(n·k) | O(n·k)，超时 |
## 记忆口诀
看到「最小化最大值 / 最大化最小值」→ 二分答案；判定函数里「能偷就偷、越早偷越好」→ 贪心。
## 解法一：二分答案 + 贪心判定（最优解）
### 思路
- 第一步：识别题型——「最小化最大值」。求的是所有合法方案中「窃取能力（方案内最大金额）」的最小值，这是二分答案的标志性问法。
- 第二步：转换问题——把「求最小能力值」转换成「给定能力值 cap，判断可不可行」。关键观察是单调性：如果能力值 cap 可行（能偷至少 k 间），那么任何比 cap 大的能力值也一定可行；比 cap 小的可能不可行。可行性关于 cap 单调递增，满足二分条件。
- 第三步：设计判定函数 canRob(cap)——只偷金额 <= cap 的房子、不偷相邻、最多能偷几间？用贪心：从左到右扫描，只要 nums[i] <= cap 就偷它（然后 i += 2 跳过相邻房子），否则跳过（i += 1）。统计偷的数量是否 >= k。
- 第四步：在值域 [min(nums), max(nums)] 上二分，找最小的可行 cap。
### 核心公式
- 二分边界：`left = min(nums)`，`right = max(nums)`
- 判定：`canRob(cap) = (贪心能偷的最大间数 >= k)`
- 贪心规则：`nums[i] <= cap → count++, i += 2；否则 i += 1`
- 二分收缩：`canRob(mid) == true → right = mid；否则 left = mid + 1`
### 图解过程
以 nums = [2,3,5,9], k = 2 为例：
- 第一步：确定值域 left=2, right=9。答案一定在这个区间内（答案必是数组中某个元素）。
- 第二步：mid=5，执行判定：i=0，nums[0]=2<=5，偷（count=1，i=2）；nums[2]=5<=5，偷（count=2，i=4）。count>=k 成立 → 5 可行，right=5。
- 第三步：mid=3，判定：i=0，nums[0]=2<=3，偷（count=1，i=2）；nums[2]=5>3，跳过（i=3）；nums[3]=9>3，跳过（i=4）。count=1<2 → 3 不可行，left=4。
- 第四步：mid=4，判定：nums[0]=2<=4 偷（count=1，i=2）；5>4、9>4 都跳过。count=1<2 → 不可行，left=5。
- 第五步：left==right==5，返回 5。
贪心为什么对（能偷就偷，不比不偷差）：
- 若 nums[i] <= cap，偷它只占用 i 和 i+1 两个位置；不偷它，最优情况也只是用 i+1 替代 i 开头去偷，能偷的数量不会更多。
- 越早偷，留给右边的位置越多，右侧的选择机会只会变多不会变少（类似「优先安排最早结束的会议」）。
### 代码示例
```java
public int minCapability(int[] nums, int k) {
    // 二分范围：答案一定落在 [数组最小值, 数组最大值] 内
    int left = Arrays.stream(nums).min().getAsInt();
    int right = Arrays.stream(nums).max().getAsInt();
    while (left < right) {
        int mid = left + (right - left) / 2;
        // 转换思维：求最小窃取能力 = 判断 cap=mid 时可不可行
        if (canRob(nums, k, mid)) {
            // mid 可行，尝试更小的能力值（保留 mid 作为候选）
            right = mid;
        } else {
            // mid 不可行，能力值必须更大
            left = mid + 1;
        }
    }
    // 循环结束时 left == right，即为最小可行能力值
    return left;
}
private boolean canRob(int[] nums, int k, int cap) {
    int count = 0;
    int i = 0;
    while (i < nums.length) {
        // 贪心：金额 <= cap 就偷当前这间，不比不偷更差
        // 注意：这里是 <= cap
        if (nums[i] <= cap) {
            i += 2;   // 偷了 i，相邻的 i+1 不能偷，直接跳过
            count++;
        } else {
            i++;      // 偷不起，跳过
        }
        // 提前达标，直接返回，剪枝加速
        if (count >= k) {
            return true;
        }
    }
    return false;
}
```
### 复杂度分析
- 时间复杂度：O(n·logU)，n 为数组长度，U 为值域大小（max-min），判定函数 O(n)，二分 logU 次（U <= 10^9，约 30 次）
- 空间复杂度：O(1)
### 优缺点
- 优点：时间复杂度与 k 无关，n=10^5、k 很大时依然高效；空间 O(1)；思路是「最小化最大值」的通用模板
- 缺点：不如打家劫舍 I~III 那样直观，需要「二分答案」的思维转换
### 测试用例
- 示例1：nums=[2,3,5,9], k=2 → 期望输出：5
- 示例2：nums=[2,7,9,3,1], k=2 → 期望输出：2
- 边界测试：nums=[1], k=1 → 期望输出：1
- 边界测试：nums=[4,4,4,4], k=2 → 期望输出：4（所有值相同，二分直接收敛）
### 边界情况分析
- 数组只有 1 个元素：left==right，直接返回该元素
- k 恰好等于 (n+1)/2：必须隔一个偷一个，贪心判定依然正确
- 所有元素相同：任意 cap>=该值都可行，二分收敛到该值
- 特殊情况：答案一定是数组中存在的某个元素，不用担心二分得到「数组里没有的值」
### 易错点提醒
- 易错点1：判定条件写成 nums[i] < cap。正确是 <= cap，能力值 cap 表示「最大能偷金额为 cap」，等于 cap 的房子可以偷
- 易错点2：二分收缩方向写反。canRob 为 true 时要往小了找（right=mid），为 false 时往大了找（left=mid+1）
- 易错点3：二分初始范围写成 [0, max]。最小值应从 min(nums) 开始，虽然不影响正确性，但多此一举；更不能写成 [0, 10^9] 浪费迭代
- 易错点4：死磕「打家劫舍 I」的 DP 求最大金额。本题求的是「最小化最大值」，DP 无法直接表达，必须转换为判定问题
### 优化版本
```java
// 判定函数的 DP 写法（与贪心等价，便于理解贪心正确性）
// f(i) = 前 i 间房子中，金额 <= cap 且不相邻的最多可偷间数
private boolean canRobDp(int[] nums, int k, int cap) {
    int f0 = 0; // f(i-2)
    int f1 = 0; // f(i-1)
    for (int num : nums) {
        int f2;
        if (num <= cap) {
            // 可偷：不偷 f1，或偷 f0+1；事实上 f0+1 >= f1 恒成立，所以必然偷
            f2 = Math.max(f1, f0 + 1);
        } else {
            // 偷不起：只能不偷
            f2 = f1;
        }
        if (f2 >= k) {
            return true;
        }
        f0 = f1;
        f1 = f2;
    }
    return false;
}
// 说明：DP 中 num <= cap 时 f0+1 一定 >= f1，所以 max 可以去掉，
// 退化后就是贪心「能偷就偷」，这正好证明了贪心的正确性
```
### 解题技巧总结
- 技巧1：看到「最小化最大值」「最大化最小值」「使XX的最大值最小」→ 立刻想到二分答案
- 技巧2：二分答案的核心是写 check 函数：把「求最优值」转为「给定值判断可行性」，可行性必须关于答案单调
- 技巧3：check 函数内部通常是贪心或简单 DP，本题贪心策略「能偷就偷」可用 DP 推导严格证明
- 技巧4：二分范围取「答案的实际值域」（本题是 [min(nums), max(nums)]），比拍脑袋的 [0, 10^9] 更严谨高效
## 核心知识点
- 二分答案（值域二分）：利用可行性的单调性，把最优化问题转化为判定问题
- 贪心判定：能偷就偷，越早偷留给右侧的机会越多
- 打家劫舍 DP 模型：f(i) = max(f(i-1), f(i-2) + 1)，可用于证明贪心正确性

## 面试回答模板
这道题问的是「窃取能力的最小值」，也就是所有合法偷法中「单间房最大金额」的最小值，属于典型的「最小化最大值」问题，套路是二分答案。我把问题转换成：给定能力值 cap，能否只偷金额不超过 cap 的房子、不偷相邻、凑够至少 k 间。这个可行性关于 cap 是单调的——cap 越大越容易做到，所以可以二分。判定函数用贪心：从左到右扫，金额不超过 cap 就偷并跳过下一间，这个贪心可以用打家劫舍的 DP 方程 f(i)=max(f(i-1), f(i-2)+1) 证明——当 nums[i] <= cap 时 f(i-2)+1 一定不小于 f(i-1)，所以必然偷。总复杂度 O(n·logU)，空间 O(1)。
