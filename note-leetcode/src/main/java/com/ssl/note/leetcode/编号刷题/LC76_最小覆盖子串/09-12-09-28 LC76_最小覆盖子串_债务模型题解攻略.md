# LC76 最小覆盖子串 —— 债务模型题解攻略
## 一、题目回顾
给定字符串 `s` 和 `t`，返回 `s` 中涵盖 `t` 所有字符的**最小子串**，不存在则返回 `""`。
示例：`s = "ADOBECODEBANC", t = "ABC"` → 输出 `"BANC"`。
注意：`t` 中字符可重复，子串中对应字符数量必须 **≥** t 中的数量（多还无所谓）。
## 二、为什么债务模型是最优解
传统滑动窗口每轮都要拿窗口词频表和 t 的词频表逐项比较，判断"是否覆盖"要 O(k)（k 为字符集大小）。
债务模型用一个**标量计数器 debt** 替代数组比较，把"是否覆盖"的判断降为 **O(1)**，且计数器只在词频**跨过临界点 0 的瞬间**更新，均摊下来全程 O(n)。
一个数组三种状态，一表多用：
| cnts[c] 的值 | 含义 |
|---|---|
| < 0 | 还欠 \|cnts[c]\| 个字符 c |
| == 0 | 恰好还清 |
| > 0 | 盈余（窗口里多出来的，可随意丢弃） |
## 三、债务模型三要素
1. **建债**：遍历 t，`cnts[t[i]]--`，把需求记为负数；总债务 `debt = t.length()`。
2. **还债**：右指针进窗 `cnts[c]++`（还债），左指针出窗 `cnts[c]--`（重新欠债）。
3. **查账**：`debt == 0` 即当前窗口已覆盖 t，可以收缩并更新答案。
## 四、算法流程（右扩左缩）
1. 右指针 `i` 每轮进窗一个字符：若进窗前 `cnts[cs[i]] < 0`（说明这个字符是"刚需"），`debt--`；然后 `cnts[cs[i]]++`。
2. 当 `debt == 0`（账已还清）：左指针 `l` 不断弹出**盈余**字符（`cnts[cs[l]] > 0` 才可弹，弹出时 `cnts[cs[l]]--`），直到窗口不能再缩。
3. 用当前窗口 `[l, i]` 更新最小长度 `len` 和起点 `start`。
4. 循环结束后，`len` 未被更新过则返回 `""`，否则返回 `s.substring(start, start + len)`。
## 五、关键代码对照
```java
for (int i = 0, l = 0; i < m; i++) {
  if (cnts[cs[i]] < 0) {   // 进窗前是欠债状态 → 这次进窗还的是真债
    debt--;
  }
  cnts[cs[i]]++;           // 进窗还债（每轮必做）
  if (debt == 0) {         // 查账：已覆盖
    while (cnts[cs[l]] > 0) { // 只弹盈余，弹到不能弹为止
      cnts[cs[l++]]--;
    }
    if (i - l + 1 < len) { // 更新最小窗口
      start = l;
      len = i - l + 1;
    }
  }
}
```
## 六、时间复杂度分析（重点）
结论：**时间 O(m + n)，空间 O(1)**（固定 256 数组），其中 m = s.length()，n = t.length()。
逐步拆解：
1. **建债**：遍历一遍 t，O(n)。
2. **右指针 i**：从 0 单调递增到 m-1，不回头，共 m 次迭代，每次进窗操作 O(1) → O(m)。
3. **左指针 l**：这是关键——`l` 在整个外循环中**也只单调右移、从不回退**，每个字符最多被弹出窗口**一次**，所以内层 while 的总执行次数全程累计 ≤ m，均摊 O(1)/轮 → 累计 O(m)。
4. **查账与更新答案**：`debt == 0` 判断和长度比较都是 O(1)。
5. 合计：O(n) + O(m) + O(m) = **O(m + n)**。
为什么不是 O(m²)：虽然 while 嵌在 for 里，但分析嵌套循环要看**指针总移动步数**而非单次最坏——i 和 l 各自最多走 m 步，"双指针单调不回头"是滑动窗口线性的根本原因。
对比朴素做法：每轮用数组逐项比较判断是否覆盖是 O(k)，总复杂度 O(m·k)；债务模型把这个 O(k) 摊销成了 O(1)，这就是它最优的原因。
空间：`int[256]` 词频数组大小与输入规模无关，视为 O(1)。
## 七、债务粒度：本题 vs LC438（找到字符串中所有字母异位词）
新题先问两问，决定债务模型怎么落地：
| 问题 | LC76（本题） | LC438 |
|---|---|---|
| "多了行不行？" | 包含即可，多还无所谓 → **按个数欠**，debt = t.length，进窗 `cnts++` 前 `< 0` 才 `debt--` | 精确匹配，多了不行 → **按种类欠**，看 `cnts == 0` |
| "窗口固定吗？" | 不固定 → l 用 while 收缩找最优 | 固定 k → l 随 i 定步移动 |
## 八、常见坑
1. **内联坑**：进窗还债每轮必做，可内联成 `if (cnts[cs[i]]++ < 0)`；但出窗**有条件**，不能写成 `cnts[cs[l]]-- > 0`，否则判断为假也会多减一次。不熟就用"改前查 → 修改 → 改后查"的显式三段式。
2. **debt 只在跨过 0 的瞬间更新**：进窗前 `< 0` 才 `debt--`，盈余字符进窗不影响 debt。
3. **收缩条件**：只有 `cnts[cs[l]] > 0`（盈余）才能弹，弹到 `== 0` 必须停，否则会把刚需字符弹掉。
4. **答案合法性**：用 `len == Integer.MAX_VALUE` 判断从未覆盖过，返回 `""`。
5. **前置剪枝**：`s.length() < t.length()` 直接返回 `""`。
