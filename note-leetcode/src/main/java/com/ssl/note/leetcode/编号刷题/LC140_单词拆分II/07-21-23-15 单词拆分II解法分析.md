# 单词拆分 II（LC140，困难）
## 题目描述
给定一个字符串 s 和一个字符串字典 wordDict，在字符串 s 中增加空格来构建一个句子，使得句子中所有的单词都在词典中。以任意顺序返回所有这些可能的句子。
注意：词典中的同一个单词可能在分段中被重复使用多次。
示例1：
```
输入：s = "catsanddog", wordDict = ["cat","cats","and","sand","dog"]
输出：["cats and dog","cat sand dog"]
```
示例2：
```
输入：s = "pineapplepenapple", wordDict = ["apple","pen","applepen","pine","pineapple"]
输出：["pine apple pen apple","pineapple pen apple","pine applepen apple"]
解释：注意你可以重复使用字典中的单词。
```
示例3：
```
输入：s = "catsandog", wordDict = ["cats","dog","sand","and","cat"]
输出：[]
```
## 解法概览
| 解法 | 思路 | 核心公式 | 时间复杂度 | 空间复杂度 |
| ----- | ----------------- | ------------ | ---------- | ---------- |
| 解法1（推荐） | DFS + 记忆化搜索（自顶向下） | `memo[start] = word + " " + dfs(end)` | O(n·2ⁿ) | O(n·2ⁿ) |
| 解法2 | 动态规划（自底向上）+ LC139可行性剪枝 | `dp[i] = s[i..j] + dp[j]` | O(n·2ⁿ) | O(n·2ⁿ) |
## 记忆口诀
**前缀是单词就切一刀，剩下的交给递归；同一个起点只算一次（记忆化）。**
## 为什么评论区说"困难题很简单"？——怎么想出来的
### 第一步：看清题目和LC139的本质区别
- LC139（单词拆分I）：只问"能不能拆分"，回答 true/false → 动态规划。
- LC140（本题）：要求**列出所有**拆分方案。
- 关键认知：**只要题目要求"枚举所有方案/所有组合/所有路径"，第一反应就该是 DFS/回溯**，而不是 DP。比如：全排列、子集、组合总和、电话号码字母组合、分割回文串——全是这个套路。所以"想不到DFS"的根源是没识别出"枚举所有"这个题型信号。
### 第二步：DFS在这题里长什么样
- 想象在字符串里"切绳子"：从左往右，枚举第一个单词在哪里结束。
- 如果 `s[start..end]` 是字典里的单词，就切一刀，剩下的 `s[end..末尾]` 是**完全一样结构的子问题** → 递归。
- "完全一样的子问题"就是DFS的入场券：问题规模变小、结构不变。
### 第三步：为什么要记忆化
- 不同切法会汇聚到同一个起点。例如 `catsanddog`：`cat+sand|...` 和 `cats+and|...` 后面都可能从 `dog` 开始递归，`dfs(7)` 会被重复计算。
- 同一个 start 对应的结果永远相同 → 用 `Map<Integer, List<String>>` 缓存，每个起点只算一次。
- 这就是"记忆化搜索 = DFS + 缓存"，等价于自顶向下的DP，但比自底向上的DP好写得多。
### 第四步：为什么说它比DP还优
- 自底向上的DP无法预知后面能不能拆分，遇到无解的超长用例会白算超时（力扣官方那个全a带一个b的用例）。
- 记忆化搜索在递归途中自然剪枝：某个 start 算出来是空列表，存进缓存，后面所有到达这里的路径立刻返回空，不再深入。
- 所以本题"困难"只是标签，DFS+记忆化 20 行就能通过。
## 解法一：DFS + 记忆化搜索（推荐）
### 思路
1. 定义 `dfs(start)`：返回子串 `s[start..末尾]` 能拼出的**所有句子列表**。
2. 枚举切分点 end，若 `s[start..end-1]` 在字典中，递归拿 `dfs(end)` 的所有句子，把当前单词拼到每个句子头部。
3. 递归边界：`start == s.length()` 时返回 `[""]`（一个含空串的列表），表示"后面没有了"，让上一层能拼出最后一个单词。
4. 用 HashMap 缓存每个 start 的结果，避免重复计算。
### 核心公式
- `dfs(start) = { word + " " + sub | word = s[start..end) ∈ 字典, sub ∈ dfs(end) }`
- 边界：`dfs(n) = [""]`
### 图解过程
以 s = "catsanddog", wordDict = ["cat","cats","and","sand","dog"] 为例：
- 第一步：dfs(0) 枚举前缀，"cat" 和 "cats" 都在字典中 → 分别递归 dfs(3) 和 dfs(4)
- 第二步：dfs(3)（子串"sanddog"）：前缀"sand"在字典 → 递归 dfs(7)
- 第三步：dfs(4)（子串"anddog"）：前缀"and"在字典 → 递归 dfs(7)（注意：dfs(7) 第二次被请求，直接走缓存）
- 第四步：dfs(7)（子串"dog"）：前缀"dog"在字典 → 递归 dfs(10)
- 第五步：dfs(10)：start == 长度，返回 [""]，逐层回填："dog" → "and dog" / "sand dog" → 最终 "cat sand dog" / "cats and dog"
- 缓存命中演示：第二次调用 dfs(7) 时直接从 memo 取到 ["dog"]，不再递归
### 代码示例
```java
public List<String> wordBreak(String s, List<String> wordDict) {
  // 字典转HashSet，contains查询O(1)
  Set<String> wordSet = new HashSet<>(wordDict);
  // 记忆化缓存：memo[start] = 从s[start..末尾]能拆出的所有句子
  Map<Integer, List<String>> memory = new HashMap<>();
  return dfs(s, 0, wordSet, memory);
}
private List<String> dfs(String s, int start, Set<String> wordSet, Map<Integer, List<String>> memory) {
  // 已经算过这个起点，直接返回缓存，避免重复计算（记忆化的核心）
  if (memory.containsKey(start)) {
    return memory.get(start);
  }
  List<String> res = new ArrayList<>();
  // 递归边界：走到末尾，返回[""]，让上一层拼出最后一个单词（且不会多出空格）
  if (start == s.length()) {
    res.add("");
    return res;
  }
  // 枚举切分点end，尝试把s[start..end-1]当作一个单词
  for (int end = start + 1; end <= s.length(); end++) {
    String word = s.substring(start, end);
    if (wordSet.contains(word)) {
      // 前缀是单词，切一刀，剩余部分交给递归（子问题结构完全相同）
      List<String> subSentences = dfs(s, end, wordSet, memory);
      // 把当前单词拼到每个后续句子的头部
      for (String sub : subSentences) {
        res.add(sub.isEmpty() ? word : word + " " + sub);
      }
    }
  }
  // 注意：即使res是空列表也要存入缓存——这就是"此路不通"的标记，实现剪枝
  memory.put(start, res);
  return res;
}
```
### 复杂度分析
- 时间复杂度：O(n·2ⁿ)。n 个起点各算一次，但每次要拼接句子，答案数量本身最坏是 2ⁿ 级别（每个字符间隙都可切或不切），输出规模决定了下界。
- 空间复杂度：O(n·2ⁿ)，缓存要存所有中间句子，递归栈最深 O(n)。
### 优缺点
- 优点：代码短、思路直白（切一刀+递归）；无解时天然剪枝，不会超时；不用先判断可行性。
- 缺点：递归有栈深度限制（本题 n≤300 没问题）；常数略大于纯DP。
### 测试用例
- 示例1："catsanddog" → ["cats and dog","cat sand dog"]
- 示例2："pineapplepenapple" → ["pine apple pen apple","pineapple pen apple","pine applepen apple"]
- 示例3（无解）："catsandog" → []
- 边界测试：s="a", dict=["a"] → ["a"]
- 极端测试：s=140个a+1个b, dict=["a","aa",...,"aaaaaaaaaa"] → []（记忆化剪枝，不超时）
### 边界情况分析
- 边界1：走到末尾 start == n，返回 [""] 而不是 []——返回[]会导致上层拼不出任何句子，结果全丢。
- 边界2：拼接时 sub 为空串不能加空格，否则句子尾部多一个空格。
- 特殊情况：字典单词可重复使用，所以不需要"用过的单词做标记"，这点和普通回溯不同。
### 易错点提醒
- 易错点1：递归边界返回空列表 [] → 正确做法是返回 [""]，否则无解。这是本题最大的坑。
- 易错点2：只缓存有解的 start → 空列表也必须缓存（`memory.put(start, res)` 无条件执行），否则无解分支会反复递归导致超时。
- 易错点3：拼接写成 `word + " " + sub` 不判空 → sub 为 "" 时尾部多空格，必须三元判断。
- 易错点4：用 `List.contains` 判断单词是否在字典 → O(m) 每次，必须转 HashSet。
### 优化版本
先用 LC139 的布尔DP做可行性预检，不可行直接返回空（对自底向上DP是必需优化；对记忆化搜索是锦上添花）：
```java
// 可行性预检：直接复用LC139的代码
private boolean canBreak(String s, Set<String> wordSet) {
  int n = s.length();
  // dp[i]表示前i个字符能否被拆分，多开一格放"空串"哨兵（见LC139题解）
  boolean[] dp = new boolean[n + 1];
  dp[0] = true;
  for (int i = 1; i <= n; i++) {
    for (int j = 0; j < i; j++) {
      if (dp[j] && wordSet.contains(s.substring(j, i))) {
        dp[i] = true;
        break;
      }
    }
  }
  return dp[n];
}
// 在wordBreak开头调用：if (!canBreak(s, wordSet)) return new ArrayList<>();
```
### 解题技巧总结
- 技巧1：题目要求"列出所有方案"→ 想DFS/回溯；只问"能否/最值"→ 想DP。
- 技巧2：DFS中出现"同一个状态被重复访问"→ 加缓存变记忆化搜索，它是最好写的DP。
- 技巧3：拼接类回溯，边界返回 `[""]` 是惯用手法，让上一层统一处理拼接。
## 解法二：动态规划（自底向上）
### 思路
- 定义 `dp[i]` = 子串 `s[i..末尾]` 能组成的所有句子列表（和解法一的记忆化语义相同，只是改成从后往前填表）。
- 转移：`dp[i] = { s[i..j] + " " + sub | s[i..j) ∈ 字典, sub ∈ dp[j], dp[j]非空 }`。
- **必须先用LC139可行性预检**：否则遇到无解超长用例，每个位置都白做大量拼接，直接超时。这是DP版不如记忆化搜索的根本原因。
### 优缺点
- 优点：无递归栈问题。
- 缺点：代码繁琐；无解时无法自动剪枝，必须额外加预检；实际面试和竞赛中都更推荐解法一。
