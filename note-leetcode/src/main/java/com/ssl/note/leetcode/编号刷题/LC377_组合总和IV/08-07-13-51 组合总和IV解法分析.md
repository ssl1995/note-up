# 组合总和IV（LC377）
## 题目描述
给你一个由 不同 整数组成的数组 nums ，和一个目标整数 target 。请你从 nums 中找出并返回总和为 target 的元素组合的个数。题目数据保证答案符合 32 位整数范围。
示例1：
```
输入：nums = [1,2,3], target = 4
输出：7
解释：所有可能的组合为：(1,1,1,1) (1,1,2) (1,2,1) (1,3) (2,1,1) (2,2) (3,1)
```
示例2：
```
输入：nums = [9], target = 3
输出：0
解释：9 比 3 大，任何组合都凑不出 3
```
- 注意：顺序不同的序列被视作不同的组合，如 (1,1,2) 和 (1,2,1) 算两种
- 提示：1 <= nums.length <= 200，1 <= nums[i] <= 1000，nums 元素互不相同，1 <= target <= 1000
- 难度：中等；标签：数组、动态规划
## 解法概览
| 解法 | 思路 | 核心公式 | 时间复杂度 | 空间复杂度 |
| ----- | ----- | ----- | ----- | ----- |
| 解法1 | 暴力回溯，枚举所有排列 | `dfs(target - num)` | O(n^m)，超时 | O(m) 递归栈 |
| 解法2 | 记忆化搜索，缓存重叠子问题 | `memo[t] = Σ memo[t-num]` | O(target × n) | O(target) |
| 解法3 | 动态规划（完全背包求排列数） | `dp[t] += dp[t-num]` | O(target × n) | O(target) |
## 记忆口诀
- 要列举用回溯，只要个数用DP
- 完全背包：组合数先物品后背包，排列数先背包后物品
- 顺序不同算不同 = 排列 = 外层target内层nums
## 前置思考：为什么回溯写法是错的/会超时
### 错误版本分析（Solution.java 初版）
初版代码 `dfs(nums, i, target - nums[i])` 把 LC39 的"防重复"模板套错了地方：
- LC39/40/216 传 start=i 或 i+1，是强制下标单调递增，避免 [1,3] 和 [3,1] 重复
- 本题恰恰要求 (1,3) 和 (3,1) 都计数，传了 i 之后选了 3 就永远回不了头选 1
- 结果：7 个答案只数出 4 个（1111、112、13、22），答案偏小
- 教训：套模板前先问自己"这题顺序算不算"，回溯的 start 参数就是为这个服务的
### 修正后的回溯（Solution1.java）仍超时
把 start 去掉、每次都从全部 nums 里选，结果正确，但递归树分支 n 个、深度 m=target/min(nums)，节点数 O(n^m) 指数级。实测 nums=[2,1,3]、target=35 就要跑 2 秒，target=1000 必然 TLE。
### 关键转折：观察题目要什么
- LC39/40/216：返回所有组合（列举），输出本身指数级，只能回溯
- 本题：返回组合的个数（计数），答案只是一个整数 → 子问题大量重叠 → 动态规划
- 重叠子问题举例：剩余 target=3 这个状态，可以从 (1,1,...) 走到，也可以从 (3) 直接走到，会被重复计算无数次
## 解法一：暴力回溯（会超时，仅作理解）
### 思路
每个位置都可以从 nums 里任选一个数（可重复选），剩余 target 减到 0 时计数加一，减到负数时剪枝返回。
### 代码示例
```java
// res 记录全局排列个数
private int res;
public int combinationSum4(int[] nums, int target) {
    if (nums == null || nums.length == 0) {
        return 0;
    }
    res = 0;
    dfs(nums, target);
    return res;
}
private void dfs(int[] nums, int target) {
    // 剪枝：剩余目标小于0，此路不通
    if (target < 0) {
        return;
    }
    // 凑出完整序列，计数加一，注意必须return
    if (target == 0) {
        res++;
        return;
    }
    // 关键：每次都从全部数字里选，不带start参数，因为顺序不同算不同（排列）
    for (int num : nums) {
        if (num > target) {
            continue;
        }
        dfs(nums, target - num);
    }
}
```
### 复杂度分析
- 时间复杂度：O(n^m)，n 为数组长度，m = target/min(nums)，指数级，target 大时超时
- 空间复杂度：O(m)，递归栈深度
### 优缺点
- 优点：思路直观，是理解本题递归结构（进而推出DP）的入口
- 缺点：大量重叠子问题被重复计算，无法通过全部测试用例
## 解法二：记忆化搜索（回溯到DP的桥梁）
### 思路
暴力回溯中，dfs(剩余t) 的结果只和 t 有关、和之前选了什么无关，因此可以把每个 t 的答案缓存起来，重复遇到直接查表。这就是"从上至下"的DP。
### 核心公式
- memo[t] = Σ memo[t - num]，对所有满足 num <= t 的 num 求和
- memo[0] = 1（空序列算一种，是递推边界）
### 代码示例
```java
public int combinationSum4(int[] nums, int target) {
    // memo[t] 表示凑出 t 的排列个数，-1 表示还没算过
    int[] memo = new int[target + 1];
    Arrays.fill(memo, -1);
    // 边界：凑出0只有空序列这1种
    memo[0] = 1;
    return dfs(nums, target, memo);
}
private int dfs(int[] nums, int t, int[] memo) {
    // 算过的直接查缓存，避免重复展开递归树
    if (memo[t] != -1) {
        return memo[t];
    }
    int sum = 0;
    // 枚举序列的最后一个数num，累加凑出 t-num 的所有方案数
    for (int num : nums) {
        if (t >= num) {
            sum += dfs(nums, t - num, memo);
        }
    }
    // 结果落缓存后再返回
    memo[t] = sum;
    return sum;
}
```
### 复杂度分析
- 时间复杂度：O(target × n)，每个 t 只计算一次，每次枚举 n 个数
- 空间复杂度：O(target)，缓存数组 + 递归栈
### 优缺点
- 优点：从暴力回溯改造而来，只需加缓存，思维过渡自然
- 缺点：仍有递归栈开销，写法不如递推简洁
## 解法三：动态规划（推荐，完全背包求排列数）
### 思路
把记忆化搜索"从下至上"地递推：dp[t] 表示总和为 t 的排列个数。对每个 t，枚举序列最后一个数 num，那么前面部分要凑出 t-num，方案数就是 dp[t-num]，全部累加。因为每个位置都可以放任意数字，所以外层遍历 target、内层遍历 nums 时，所有顺序自然都被统计到。
### 核心公式
- 状态定义：dp[t] = 总和为 t 的排列个数
- 状态转移：dp[t] += dp[t - num]（对每个满足 num <= t 的 num）
- 初始状态：dp[0] = 1（空序列 1 种，是递推的源头；也让"某个 num 恰好等于 t"能贡献 1 种）
- 答案：dp[target]
### 图解过程（nums=[1,2,3], target=4）
- 初始：dp = [1, 0, 0, 0, 0]，dp[0]=1 是递推边界
- 第一步 t=1：只能从 dp[0]（结尾放1）转移 → dp[1]=1，对应 (1)
- 第二步 t=2：dp[1]（结尾1）+ dp[0]（结尾2）= 1+1=2，对应 (1,1) (2)
- 第三步 t=3：dp[2]+dp[1]+dp[0] = 2+1+1=4，对应 (1,1,1) (1,2) (2,1) (3)
- 第四步 t=4：dp[3]+dp[2]+dp[1] = 4+2+1=7，对应题目列出的 7 种
- 观察：每个 dp[t] 都把"以任意 num 结尾"的情况全部累加，(1,3) 和 (3,1) 分别在不同分支被数到
### 代码示例
```java
public int combinationSum4(int[] nums, int target) {
    if (nums == null || nums.length == 0) {
        return 0;
    }
    // dp[t] 表示总和为 t 的排列个数
    int[] dp = new int[target + 1];
    // 空序列算1种，作为递推边界
    dp[0] = 1;
    // 外层必须遍历target（背包），这样每个t都允许任意数结尾，数出来的才是排列
    for (int t = 1; t <= target; t++) {
        // 内层遍历nums（物品），枚举序列最后一个数
        for (int num : nums) {
            if (t >= num) {
                // 最后一个数是num，前面凑出t-num的方案数全部累加
                dp[t] += dp[t - num];
            }
        }
    }
    return dp[target];
}
```
### 复杂度分析
- 时间复杂度：O(target × n)，target 最大 1000、n 最大 200，约 2×10^5 次操作
- 空间复杂度：O(target)，一维 dp 数组
### 优缺点
- 优点：效率最高，代码极简，是本题的标准解法
- 缺点：状态定义和遍历顺序需要理解透彻，否则容易和组合数写法混淆
### 测试用例
- 示例1：nums=[1,2,3], target=4 → 期望输出：7
- 示例2：nums=[9], target=3 → 期望输出：0
- 边界测试：nums=[1], target=1 → 期望输出：1
- 边界测试：nums=[1], target=1000 → 期望输出：1（全1序列只有一种）
### 边界情况分析
- nums 为空或 null：直接返回 0
- nums 中所有数都大于 target：dp[target] 保持 0，自然返回 0，无需特判
- dp[0]=1 的意义：空序列占 1 种，保证 num==t 时 dp[t] 能从 dp[0] 加上 1；题目数据保证 nums 元素为正，不会导致 0 被无限重复计算
- 溢出：题目保证答案在 32 位整数范围内，int 即可；若面试中被追问可提 long
### 易错点提醒
- 易错点1：套用 LC39 模板传 start=i，把排列数算成组合数。本题顺序不同算不同，回溯必须每次从全部数字选，DP 必须外层 target 内层 nums
- 易错点2：内外层遍历写反。外层 nums 内层 target 是 LC518 零钱兑换II 的写法，数的是组合；本题数排列必须反过来
- 易错点3：忘记 dp[0]=1。没有它所有 dp[t] 都是 0，递推无法启动
- 易错点4：回溯版 target==0 计数后忘记 return，虽然正数数组下碰巧不重复计数，但属于隐患
### 优化版本（二维DP视角，帮助理解"排列"本质）
```java
// dp[i][j] 表示序列长度恰好为 i、和为 j 的排列数，答案是 Σ dp[i][target]
int[][] dp = new int[target + 1][target + 1];
// 长度为0时和只能为0，占1种
dp[0][0] = 1;
int res = 0;
for (int i = 1; i <= target; i++) {
    for (int j = 0; j <= target; j++) {
        for (int num : nums) {
            if (j >= num) {
                // 第i个位置放num，前i-1个位置凑出j-num
                dp[i][j] += dp[i - 1][j - num];
            }
        }
    }
    // 所有长度下凑出target的方案数累加
    res += dp[i][target];
}
return res;
```
### 解题技巧总结
- 技巧1：看到"返回个数"先想 DP，看到"返回所有方案"才想回溯
- 技巧2：完全背包家族中，组合与排列只差遍历顺序：组合外物品内背包，排列外背包内物品
- 技巧3：计数类DP的边界通常是 dp[0]=1，代表"什么都不选"这一种方案
- 技巧4：暴力回溯 → 发现重叠子问题 → 加缓存 → 改递推，是想不出DP时的标准推导路径

## 面试回答模板
这道题名字叫组合总和，但题目明确说顺序不同算不同，所以本质是求排列数。因为只要个数不要具体方案，我考虑动态规划。定义 dp[t] 表示和为 t 的排列数，转移时枚举序列最后一个数 num，dp[t] 累加所有 dp[t-num]，边界 dp[0]=1 表示空序列。这里有个关键细节：必须外层遍历 target、内层遍历 nums，这样每个和都允许任意数字结尾，统计的才是排列；反过来写就是 LC518 求组合数的写法了。时间复杂度 O(target×n)，空间 O(target)。如果用回溯暴力枚举也能做对但会超时，因为存在大量重叠子问题，这正是用 DP 的信号。进阶如果数组含负数，需要限制每个数字的使用次数，否则序列可以无限长导致答案无限大。
